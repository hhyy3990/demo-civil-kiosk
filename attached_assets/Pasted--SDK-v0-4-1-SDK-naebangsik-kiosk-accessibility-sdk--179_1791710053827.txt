# 무인민원발급기 — 공통 SDK v0.4.1 업데이트 및 기존 오류 재검증

첨부한 파일은 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.4.1`입니다.

현재 무인민원발급기에는 SDK v0.4.0이 설치돼 있으며, 개발용 `?viewport-test=1` 화면을 통해 방법 B 하단 조작 모드의 60%·70%·80%를 시험할 수 있습니다.

이번 작업에서는 SDK를 v0.4.1로 교체하고, 실제 사용 중 발견된 문제들이 해결됐는지 검증해 주세요.

## 1. SDK 교체
- 첨부 파일의 패키지명과 버전 확인 후 v0.4.1 설치
- 기존 v0.4.0 및 이전 tarball 보존
- SDK 소스와 중앙 서버·DB는 수정하지 않기
- 기존 `?viewport-test=1` 테스트 기능 유지

## 2. 스크롤 안내 검증 — 최우선

v0.4.1에서는 일반 메뉴 버튼과 안내 pill이 일부 겹칠 수 있도록 SDK 정책을 변경했습니다.

다음 상태에서 안내를 확인해 주세요.

- 맨 위: 아래에 내용이 남아 있으면 안내 표시
- 25%·50%·75%: 안내 유지
- 최하단: 안내 숨김
- 다시 위로 이동: 안내 재표시

일반 증명서 메뉴와 안내가 조금 겹치는 것은 허용합니다.

다만 고정된 처음화면·전화면·확인 버튼은 절대 가리지 않아야 합니다.

기존 공통 문구인 `↓ 아래에도 내용이 있어요`, `↓ 아래에도 버튼이 있어요`를 유지해 주세요.

## 3. 발급 불가 안내 모달 스크롤 점프

이전 v0.4.0에서는 발급 불가 메뉴의 안내 모달을 열면 `.stage.scrollTop`이 724px에서 549px 또는 389px로 변경되는 현상이 있었습니다.

이번 v0.4.1 독립 fixture에서는 모달 점프가 재현되지 않았으므로 무인민원발급기 실제 화면에서 반드시 다시 확인해야 합니다.

- 메뉴를 아래쪽으로 스크롤
- 발급 불가 항목 클릭
- 모달 열기 직전·직후 scrollTop 비교
- 모달 닫기 직후와 1초 후 위치 비교
- 기존 위치로 유지되는지 확인
- QR 설정 모달도 별도로 열고 닫아 비교

여전히 점프한다면 해결됐다고 주장하지 말고 SDK 문제인지 호스트 모달 문제인지 원인을 조사해 주세요.

원인 확인 없이 스크롤 위치를 강제로 되돌리는 임시 코드는 추가하지 마세요.

## 4. 숫자 키패드 접근성 검증

사용자가 직접 테스트했을 때 숫자 7·8·9·0이 아래쪽에 가려지고, 끝까지 스크롤할 수 없는 사례가 있었습니다.

이후 Chromium 자동화에서는 최하단까지 스와이프해서 모든 숫자를 누르는 데 성공했지만, 사용자 환경의 문제가 해결됐는지는 아직 불확실합니다.

하단 60%·70%·80%와 아주 큰 글씨·큰 버튼·고대비 조합에서 다음을 확인해 주세요.

- 숫자 0~9 전부 화면에 노출 가능
- 마지막 줄까지 스와이프로 접근 가능
- 실제 포인터·터치 입력 성공
- 고정 하단 조작부와 키패드 겹침 여부
- 스크롤 튐 및 스크롤 범위 부족 여부

## 5. 개발용 하단 조작 모드 유지

현재 중앙 QR에는 하단 조작 비율이 저장되지 않으므로, 테스트에서는 SDK 공개 API의 `setViewportMode()`를 활용합니다.

기존 `?viewport-test=1` 기능이 있다면 그대로 유지하고, 사용자가 Replit Preview에서 60%·70%·80%를 직접 선택하여 비교할 수 있도록 해 주세요.

실제 QR 프로필을 스캔한 뒤에도 개발용 테스트 옵션으로 하단 비율을 별도로 선택할 수 있어야 합니다. 단, 이것이 QR에 저장된 설정인 것처럼 표현하지 마세요.

일반 사용자 화면에는 개발용 테스트 도구가 나타나지 않아야 합니다.

- 320×844, 390×844, 1080×1920 검증
