가상 무인민원발급기 웹 데모를 새 프로젝트로 만들어줘.
이 프로젝트는 공모전/QR/SDK와는 일단 별개인 독립 데모로 만들고, 나중에 접근성 SDK와 QR 기반 프로필 적용 기능을 붙일 수 있도록 구조만 깔끔하게 만들어줘.
지금 단계에서는 QR, 내 방식 QR, 접근성 프로필 UI는 절대 넣지 말고, 순수하게 한국 행정복지센터/동사무소에서 볼 법한 무인민원발급기 데모를 구현해줘.
1. 프로젝트 목표
- 실제 무인민원발급기처럼 보이는 가상 키오스크 웹 데모
- 현재는 주민등록등본 발급 시나리오만 작동
- 다만 첫 화면에는 실제 기기처럼 여러 증명서 발급 버튼을 그대로 보여줘야 함
- 화면 어디엔가 “데모 버전으로 현재는 주민등록등본 발급만 제공” 이라는 안내를 자연스럽게 표시
- 너무 감성적이거나 세련된 카페 느낌 말고, 공공기관 키오스크처럼 딱딱하고 실무적인 화면으로 구성
2. 디자인 방향
다음 방향을 꼭 지켜줘.
전체 분위기
- 실제 행정복지센터, 주민센터, 무인민원발급기 느낌
- 감성 UI, 라운드가 과한 카드형 앱 느낌 X
- 너무 현대적인 스타트업 느낌 X
- 투박하고 공공기관스러운 인터페이스
- 컬러는 하늘색/파란색/회색/흰색/연녹색 정도의 공공기관풍
- 강조 버튼은 파란색 확인 버튼, 이전/처음 버튼은 구분되는 색으로
- 배경은 흰색/연회색, 패널은 연파랑이나 회색 계열
- 버튼은 직사각형 중심, 너무 예쁘게 다듬지 말고 기기 UI 같은 느낌
- 상단 제목, 안내 문구, 큰 선택 버튼, 하단 네비게이션 구조를 사용
레이아웃
- 세로형 키오스크 화면에 최적화된 레이아웃
- 웹 브라우저에서 실행되지만 실제 키오스크 화면처럼 보이도록 중앙에 기기 화면 형태로 구성
- 하단에는 실제 기기처럼
  - 처음화면
  - 전화면
  - 확인
    같은 조작 버튼이 보이게 해줘
- 단계별 진행 흐름이 자연스럽게 보이게 구성
3. 초기 화면 요구사항
첫 화면은 발급을 원하는 증명서를 선택하는 화면처럼 만들어줘.
첫 화면에 보여줄 증명서 버튼 예시
- 주민등록
- 지적, 토지, 건축
- 차량
- 보건복지
- 농지대장, 농업경영체
- 가족관계등록부
- 제적부
- 병적증명서
- 지방세
- 어선원부
- 부동산등기사항증명서
- 교육제증명
- 국세증명
- 건강보험
- 고용·산재보험
- 여권
- 국민연금
- 교통(경찰청)
이 버튼들을 첫 화면에 여러 개 그대로 보이게 해줘.
다만 실제 동작은 주민등록만 활성화하거나, 나머지는 눌렀을 때
“데모 버전에서는 현재 주민등록등본 발급만 제공됩니다.”
라는 안내가 뜨도록 해줘.
첫 화면 안내
- 상단 큰 제목: 발급을 원하시는 증명서를 선택하십시오.
- 서브 문구: 현재는 주민등록등본 발급 기능만 시연할 수 있습니다.
- 별도의 작은 안내 박스나 배너로:
  - 데모 버전 안내
  - 현재 주민등록등본 발급만 제공됩니다.
    를 넣어줘
4. 구현할 실제 동작 시나리오
주민등록등본 발급 흐름만 실제 작동하게 해줘.
권장 흐름은 아래처럼 구현해줘.
Step 1. 메인 화면
- 증명서 종류 선택
- 주민등록 버튼 선택 시 다음 단계로 이동
Step 2. 주민등록 문서 선택
- 주민등록표(등본)
- 주민등록표(초본)
  두 버튼을 보여주되,
- 등본만 실제 진행 가능
- 초본은 비활성화하거나 “준비 중” 표시 가능
Step 3. 주민등록번호 입력
- 제목: 주민등록번호를 입력한 후 확인을 누르십시오.
- 숫자 입력 UI 표시
- 숫자 키패드(0~9), 삭제, 정정 버튼 구현
- 화면 한쪽에 데모 안내로:
  - 데모 버전이므로 실제 주민등록번호가 아닌 임의의 숫자를 입력해 주세요.
- 실제 검증은 엄격하지 않아도 되며, 형식상 13자리 정도 입력되면 다음으로 진행 가능하게 해줘
- 개인정보를 실제로 저장하거나 서버에 보내지 말고 프론트 상태로만 처리
Step 4. 본인확인 안내
- 실제 지문인식기 연동은 하지 말고, 시뮬레이션 화면으로 구성
- 안내 문구:
  - 지문인식기에 오른손 엄지손가락을 올려주세요.
- 화면에 지문 확인 버튼 또는 지문 인식 완료 버튼을 두어 다음 단계로 진행 가능하게 해줘
- 기기 느낌을 위해 지문 그림/안내 패널이 있으면 좋음
Step 5. 선택사항/출력 정보 선택
너무 복잡하지 않되, 무인민원발급기 느낌을 주기 위해 몇 가지 옵션 선택 화면을 구현해줘.
예시:
- 주소 공개 / 비공개
- 과거 주소 변동 사항 포함 / 미포함
- 세대 구성 사유 포함 / 미포함
이 옵션들은 실제 기기처럼 선택 버튼 형태로 보이게 해줘.
Step 6. 수수료 면제 여부 선택
- 수수료 면제 대상자
- 수수료 면제 대상자 아님
  두 개 정도의 큰 선택 버튼으로 구성
- 기본적으로 어느 쪽이든 다음 단계 진행 가능
Step 7. 발급 부수 입력
- 제목: 발급할 부수를 입력한 후 확인을 누르십시오.
- 숫자 키패드 또는 1~9 선택 UI
- 기본값 1부
- 최대 9부까지만 가능하게 해줘
- 좌측에는 지금까지 선택한 정보 요약을 보여주면 좋음
Step 8. 신청 내용 확인
- 지금까지의 선택 내용을 요약해서 보여줘
- 예:
  - 신청증명서: 주민등록표(등본)
  - 신청부수: 1부
  - 선택항목: 주소공개, 과거주소 미포함 등
  - 수수료: 200원
- 결제 방식 선택 버튼:
  - 카드
  - 현금
- 둘 중 아무거나 누르면 다음 단계로 진행
Step 9. 인쇄 중
- 인쇄 중입니다. 잠시만 기다려 주십시오.
- 진행 중 느낌의 화면
- 2~3초 후 자동으로 완료 화면으로 이동
Step 10. 발급 완료
- 발급이 완료되었습니다.
- 증명서 출력구에서 서류를 받아 주세요.
- 처음 화면으로 버튼 제공
- 필요하면 추가 발급 / 종료 느낌 버튼도 가능하지만 필수는 아님
5. 화면 곳곳의 데모 안내 문구
이 프로젝트는 실제 기기를 재현하는 데모이므로, 과하지 않게 아래 안내를 적절히 넣어줘.
첫 화면
- 데모 버전으로 현재는 주민등록등본 발급 기능만 제공됩니다.
주민번호 입력 화면
- 데모 버전이므로 임의의 숫자를 입력해 주세요.
지문 확인 화면
- 실제 지문 인식 대신 화면 내 확인 버튼으로 진행할 수 있습니다.
결제 화면
- 데모 버전이므로 실제 결제는 진행되지 않습니다.
발급 완료 화면
- 실제 문서는 출력되지 않는 시뮬레이션 화면입니다.
이 문구들은 너무 튀지 않게,
안내 박스나 하단 작은 배너 정도로 공공기관 화면 분위기를 해치지 않게 넣어줘.
6. 기술 요구사항
- React + TypeScript 기반으로 구현
- 로컬 상태(state)만 사용해도 충분함
- 데이터베이스는 없어도 됨
- 실제 결제/실제 지문/실제 주민번호 검증/실제 문서 출력은 구현하지 말 것
- 코드는 나중에 확장하기 좋게 단계별 상태와 화면 컴포넌트를 분리
- 예:
  - MainMenuScreen
  - ResidentTypeScreen
  - ResidentNumberInputScreen
  - FingerprintGuideScreen
  - OptionsScreen
  - FeeWaiverScreen
  - CopiesInputScreen
  - PaymentScreen
  - PrintingScreen
  - CompleteScreen
처럼 분리해줘
7. 앞으로 SDK 붙이기 좋게 고려할 점
지금은 QR/SDK를 넣지 말되, 나중에 붙이기 쉽게 다음을 고려해줘.
- 화면 루트에 일관된 최상위 컨테이너 사용
- 주요 버튼에 안정적인 식별자 부여
  - 예: main-resident-button
  - next-confirm-button
  - payment-card-button
- 각 화면 단계에 이름 부여
  - 예: main-menu, resident-type, resident-number, options, copies, payment, printing, complete
- 텍스트, 버튼, 하단 조작 영역이 나중에 스타일 조정 가능하도록 구조화
- 하지만 지금 단계에서는 접근성 SDK UI, QR 불러오기 UI, AI UI는 전혀 노출하지 말 것
8. 디자인 완성도 체크 기준
다음이 충족되도록 만들어줘.
- 첫 인상이 카페 사이트나 일반 모바일 앱이 아니라 무인민원발급기처럼 보이는가
- 첫 화면에 여러 증명서 종류가 보여 실제 기기 느낌이 나는가
- 주민등록등본 발급 흐름이 한 단계씩 자연스럽게 진행되는가
- 처음화면 / 전화면 / 확인 등 기기스러운 조작 체계가 보이는가
- 데모 안내 문구가 있지만 분위기를 깨지 않는가
- 너무 감성적이지 않고 공공기관 기기다운 딱딱한 느낌이 나는가
9. 검증 요청
구현 후 아래를 확인해줘.
- 첫 화면에서 여러 증명서 버튼이 보이는지
- 주민등록 → 등본 발급 흐름이 끝까지 작동하는지
- 주민번호 입력, 옵션 선택, 발급 부수, 결제, 인쇄 완료까지 전부 진행되는지
- 데모 안내 문구가 각 필요 화면에 들어가는지
- 데스크톱과 모바일 세로 화면에서 모두 확인해줘
- 가로 넘침, 버튼 겹침, 잘림이 없는지 확인해줘
10. 금지 사항
- QR 관련 문구/기능 추가 금지
- 내 방식 QR, 접근성 프로필, 공모전 소개 화면 추가 금지
- 감성적인 카페/웜톤 랜딩페이지 스타일 금지
- 실제 정부 기관 로고를 그대로 복제하지는 말고, 공공기관풍의 일반적인 UI 느낌만 참고
- 지금 단계에서 납세증명서, 가족관계증명서 등 다른 상세 시나리오는 구현하지 말고 주민등록등본만 구현
