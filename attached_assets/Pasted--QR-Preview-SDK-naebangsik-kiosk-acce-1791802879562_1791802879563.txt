# 내 방식 QR — 무인민원발급기 넓은 Preview 상단 헤더 잘림 진단 및 최소 수정

현재 무인민원발급기 프로젝트에는 공통 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.5`가 설치되어 있습니다.

기존 작업을 통해 다음 문제는 해결했습니다.

- 하단 60·70·80%에서 콘텐츠 제목 잘림
- 화면 전환 시 스크롤 위치 잔류
- 스크롤 안내로 인한 위치 되돌아감
- QR 도크의 하단 모드 동기화 누락
- 360×667 마지막 증명서 메뉴 아래 165px 중복 여백

그러나 사용자가 실제 Replit Preview를 넓은 새 브라우저 창에서 확인했을 때, **스크롤을 끝까지 위로 올렸는데도 무인민원발급기 상단 헤더와 로고가 브라우저 위쪽으로 잘리는 문제**가 남아 있습니다.

사용자 스크린샷에서는 다음 현상이 보입니다.

- 키오스크의 상단 로고와 '무인민원발급' 제목이 부분적으로 잘림
- 오른쪽 상단 '처음 화면' 버튼도 상단 경계에 걸림
- 증명서 안내문과 18개 메뉴는 화면에 표시
- 화면 하단의 '내 QR로 화면 설정' 도크는 정상적으로 표시
- 사용자는 스크롤을 가능한 한 위로 올린 상태라고 보고함

이번에는 기존 SDK의 `.stage` 내부 첫 제목 검사만으로 정상 판정하지 마세요.

**키오스크 바깥 프레임, 로고, 전체 헤더까지 실제 브라우저 화면 안에 온전히 표시되는지 확인하는 것이 핵심입니다.**

## 1. 문제 재현

실제 Replit Preview와 넓은 새 브라우저 탭에서 문제를 재현합니다.

우선 다음 조건을 확인합니다.

- 1440×900
- 1920×1080
- 실제 Preview 새 창의 사용 가능한 viewport 크기
- 브라우저 확대율 100%
- QR 미적용 기본 상태
- v3 viewportMode:null
- 큰 글씨·큰 버튼·고대비 + 하단 60·70·80%

브라우저 전체 크기와 실제 웹 콘텐츠 영역 크기는 다를 수 있으므로 window.innerWidth/innerHeight를 기준으로 측정합니다.

다음 상황을 구분합니다.

A. 새 탭 최초 진입

B. 새로고침 후

C. QR 프로필 적용 후

D. 증명서 발급 화면 진입 후

E. 발급 화면에서 처음화면 복귀 후

F. 브라우저 창 크기를 변경한 후

특정 화면 전환 후에만 발생하는지, 최초 진입부터 발생하는지 확인합니다.

## 2. 전체 프레임과 헤더 좌표 측정

다음 요소의 실제 DOM을 찾아 boundingClientRect를 기록합니다.

- 키오스크 전체 외부 프레임
- 키오스크 본체 컨테이너
- 키오스크 상단 헤더
- 로고
- '무인민원발급' 제목
- 오른쪽 상단 '처음 화면' 버튼
- main.stage
- QR 도크
- 하단 고정 조작부

기록 항목:

- top
- bottom
- height
- scrollTop
- scrollHeight
- clientHeight
- computed overflow
- position
- transform
- display
- align-items
- justify-content
- min-height
- max-height
- height

**헤더 자체가 viewport 위로 밀려난 것인지, 상위 요소의 overflow에 의해 잘린 것인지 구분해 주세요.**

## 3. 스크롤 소유자 전수 확인

기존 검증에서는 `.stage`가 정상적인 스크롤 소유자였습니다.

하지만 이번 문제는 `.stage` 외부에서 발생할 수 있습니다.

다음을 확인합니다.

- window.scrollY
- document.scrollingElement.scrollTop
- html.scrollTop
- body.scrollTop
- 키오스크 외부 프레임 scrollTop
- stage.scrollTop
- 상위 스크롤 컨테이너의 scrollTop

각 요소를 가능한 최상단으로 이동한 뒤에도 헤더가 잘리는지 확인합니다.

단, 이것은 진단용 조작이며 실제 앱에 강제 scrollTo 코드를 추가하지 않습니다.

**모든 스크롤 위치가 0인데 프레임 top이 음수라면, 스크롤 문제가 아니라 레이아웃 배치 문제일 가능성이 높습니다.**

## 4. 외부 프레임 중앙 정렬 분석

특히 다음 구조를 조사합니다.

- body 또는 앱 루트의 flex/grid 중앙 정렬
- 키오스크 프레임의 고정 높이
- min-height
- align-items:center
- justify-content:center
- 상위 컨테이너의 overflow:hidden
- viewport보다 큰 프레임을 중앙 배치하는 구조
- 브라우저 높이가 줄었을 때의 반응형 처리

예를 들어 키오스크 프레임이 viewport보다 높은데 세로 중앙 정렬되면 프레임 상단이 음수 좌표로 밀릴 수 있습니다.

이 가능성을 실제 DOM 좌표와 계산된 CSS로 확인해 주세요.

가설만으로 수정하지 마세요.

## 5. SDK 영향과 호스트 CSS 영향 구분

다음 상태를 비교합니다.

- SDK 프로필 미적용
- viewportMode:null
- 하단 60%
- 하단 70%
- 하단 80%

SDK가 바꾸는 영역은 무엇인지, 호스트가 관리하는 프레임과 헤더는 무엇인지 구분합니다.

특히 다음을 확인합니다.

- SDK가 전체 프레임의 height 또는 transform을 변경하는가?
- SDK가 헤더 상위 컨테이너의 overflow를 변경하는가?
- SDK가 적용되기 전에도 헤더가 잘리는가?
- 프레임 중앙 정렬만으로 문제가 재현되는가?
- QR 도크 활성화가 외부 프레임의 위치에 영향을 주는가?

**SDK 문제가 아니라면 SDK를 수정하지 않습니다.**

## 6. 독립적인 원인 확인

원인이 의심되는 CSS 속성을 찾았다면 브라우저 DevTools에서 한 번에 하나씩 임시 변경해 봅니다.

예시:

- 부모 justify-content:center → flex-start
- align-items:center → flex-start
- 고정 height → 콘텐츠와 viewport에 맞는 높이
- min-height 조정
- 바깥 컨테이너의 overflow 변경

각 실험에서 다음을 기록합니다.

- 헤더 좌표 변화
- 로고 전체 표시 여부
- 처음 화면 버튼 표시 및 클릭
- stage 영역 변화
- QR 도크 위치
- 하단 고정 조작부 위치
- 새로운 이중 스크롤 발생 여부

임시 실험 후 원래 상태를 복원합니다.

**원인으로 확인된 속성만 실제 수정 대상으로 선정합니다.**

## 7. 최소 수정 원칙

호스트의 외부 프레임 레이아웃이 원인이라고 명확히 확인되면, 해당 호스트 CSS 또는 프레임 구조만 최소한으로 수정해 주세요.

허용되는 방향:

- viewport보다 프레임이 높을 때 안전한 상단 정렬
- 헤더가 잘리지 않는 반응형 외부 레이아웃
- 필요한 경우 프레임 높이 계산 보완
- 정상적인 스크롤 영역과 헤더 영역 분리

금지하는 방향:

- SDK 내부 파일 수정
- node_modules 수정
- 전체 키오스크를 transform:scale()로 축소
- 기존 글씨·버튼 크기 축소
- 헤더를 임의 픽셀만큼 아래로 밀기
- 특정 화면 크기에서만 적용되는 임시 보정
- 강제 scrollTo 타이머 추가
- 기존 QR 도크·하단 버튼 제거
- 업무 로직 변경

수정 후에도 SDK의 하단 viewport 계약과 호스트의 스크롤 소유자가 유지돼야 합니다.

원인이 SDK 공통 처리에 있다면 호스트 우회 코드를 작성하지 말고 원인을 보고한 뒤 작업을 중단해 주세요.

### 최종 성공 기준

**1. 넓은 Preview에서 키오스크 전체 헤더와 로고가 온전히 표시됩니다.**

**2. 스크롤을 맨 위로 올렸을 때 프레임 자체가 브라우저 상단 밖에 배치되지 않습니다.**

**3. 첫 화면뿐 아니라 업무 중 처음화면 복귀 후에도 동일하게 정상 표시됩니다.**

**6. SDK 공통 문제라면 호스트에 임시 우회 코드를 추가하지 않고 진단 결과를 보고합니다.**

실패한 조건이나 사용자 Preview에서만 남는 차이는 숨기지 말고 측정값과 함께 보고해 주세요.
