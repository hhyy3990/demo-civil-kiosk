# 무인민원발급기 — 공통 SDK v0.3.3 업데이트 및 추가 메뉴 안내 검증

첨부한 파일은 `@naebangsik/kiosk-accessibility-sdk@0.3.3`입니다.

현재 무인민원발급기에는 SDK v0.3.2가 적용되어 있으며, 기존 스크롤 문제는 `src/styles.css`의 세로 overscroll 설정 수정으로 해결했습니다.

이번 작업에서는 SDK v0.3.3을 설치하고 공통 '추가 메뉴 안내' 기능을 실제 무인민원발급기에 연결해 주세요.

## 1. SDK 설치

- 첨부한 tarball의 패키지명과 버전 확인
- 기존 v0.3.2에서 v0.3.3으로 업데이트
- 이전 tarball 보존
- SDK 내부 소스 수정 금지
- 기존 터치 스크롤 CSS 수정 유지

## 2. 추가 메뉴 안내 연결

기존 어댑터의 `getLayoutRegions()`에 새 SDK가 사용하는 `menuItems`와 `menuMessage`를 등록해 주세요.

안내 문구:

"아래에도 증명서 메뉴가 있습니다. 화면을 위로 밀어보세요."

구현 조건:

- 실제 18개 증명서 메뉴 DOM 요소 등록
- 메뉴와 무관한 처음화면·전화면·QR 설정 버튼은 menuItems에서 제외
- 현재 문서 스크롤 구조에 맞는 실제 스크롤 요소 등록
- 하단 고정 조작부 등록 유지
- 메뉴 화면이 아닐 때는 해당 메뉴 목록을 등록하지 않음
- 안내 UI 자체는 SDK가 생성하도록 하고 호스트에서 별도 구현하지 않음
- QR을 스캔하지 않은 기본 화면에서도 SDK 안내가 활성화되도록 연결

필요하면 메뉴 요소에 `data-a11y-menu-item` 속성을 추가해도 됩니다.

## 3. 실제 안내 표시 검증

320×844 및 390×844에서 다음 상태를 확인해 주세요.

A. QR 적용 전 기본 화면

B. 큰 글씨·큰 버튼·고대비 적용 후

C. 마지막 메뉴까지 스크롤한 화면

D. 맨 위로 다시 스크롤한 화면

예상 동작:

- 아래에 메뉴가 남아 있으면 안내 표시
- 마지막 메뉴가 보이면 안내 숨김
- 다시 위로 올라오면 안내 재표시
- 모든 메뉴가 보이면 안내 표시하지 않음
- 안내가 메뉴나 하단 고정 버튼을 가리지 않음
- 안내를 직접 누르지 않아도 기존 스크롤 정상 작동
- 메뉴 마지막 항목을 실제 좌표로 클릭 가능

1080×1920에서도 확인하되, 실제로 숨겨진 메뉴가 없다면 안내가 나타나지 않아야 합니다.

## 4. 스크롤 회귀 테스트

직전 작업에서 수정한 아래 CSS는 유지해 주세요.

```css
overscroll-behavior-x: contain;
overscroll-behavior-y: auto;
```

다음 동작을 재검증합니다.

- 메뉴 영역에서 터치 스크롤
- 마우스 휠 스크롤
- 마지막 메뉴까지 이동
- QR 적용 전후 스크롤
- 처음화면 복귀 시 스크롤 정상화

실제 터치 기기가 없다면 브라우저 시뮬레이션과 구분해 주세요.

## 5. 기존 기능 유지

- 증명서 메뉴 18개
- 개인정보 보호 및 지문인식 안내
- 주민등록등본 발급 전체 흐름
- QR 프로필 v1/v2 적용
- 큰 글씨·큰 버튼·고대비
- 하단 조작
- 스마트 길잡이·음성 안내
- 세션 초기화
- 화면 단순화 기능 제거 상태

## 6. 테스트

실제 Chromium 브라우저에서 메뉴 요소의 위치를 측정해 주세요.

다음 항목을 보고합니다.

- 초기 화면에서 가려진 메뉴 수
- 안내 표시 여부
- 마지막 메뉴 도달 시 안내가 사라지는지
- 다시 올라왔을 때 재표시되는지
- 안내 UI와 메뉴·하단 조작 버튼의 겹침 여부
- 실제 클릭 hit-test 결과
- QR 적용 전후 비교
- SDK 자동 진단 결과
- 320×844, 390×844, 1080×1920 결과

안내 UI가 메뉴나 버튼 클릭을 방해한다면 성공으로 보고하지 말고 원인을 분석해 주세요.
