# 무인민원발급기 — 공통 SDK v0.5.15 업데이트 및 전체 회귀 검증

## 0. 작업 대상 및 목적

현재 프로젝트는 **무인민원발급기 Replit**입니다.

업로드된 `naebangsik-kiosk-accessibility-sdk-0.5.15.tgz`를 사용하여 공통 접근성 SDK를 기존 v0.5.14에서 **v0.5.15로 업데이트**해 주세요.

패키지명: `@naebangsik/kiosk-accessibility-sdk`

이번 업데이트의 목적은 데모커피에서 발견된 **공통 안내창이 주요 업무 버튼을 가리는 문제를 해결한 SDK를 무인민원발급기에도 적용**하는 것입니다.

기존의 '접근성 체험하기' 기능, 민원발급 절차, QR 스캔 및 접근성 설정은 모두 유지합니다.

**새로운 기능을 추가하지 말고 SDK 설치 및 기존 기능 회귀 검증에 집중하세요.**

## 1. 기존 구현 확인

먼저 다음을 조사하세요.

- 현재 설치된 SDK 버전
- QR v1~v4 프로필 적용 구조
- Development 전용 '접근성 체험하기' 버튼
- 고정 QR v4 체험 프로필
- `setEasyLanguageState()` 연결
- `setGuideState()` 및 단계별 `stepId`
- 주요 업무 버튼과 회피 영역의 SDK 등록 구조
- 숫자 키패드·발급 옵션·부수·결제 단계
- 완료 후 15초 자동 복귀
- 시간 연장 및 수동 처음으로
- `endSession()` 초기화
- 기존 테스트 및 빌드 구조

기존 정상 동작하는 호스트 코드는 불필요하게 변경하지 마세요.

## 2. SDK v0.5.15 설치

업로드된 공식 tarball을 사용하세요.

설치 후 다음을 확인합니다.

- 설치된 패키지 버전이 정확히 `0.5.15`
- 패키지명 일치
- package.json 및 lockfile 반영
- 기존 SDK 공개 API 사용 가능
- QR v1~v4 지원 유지
- 공통 안내창 API 유지
- 완료 후 자동 복귀 API 유지
- 타입 검사·빌드 성공

기존 v0.5.14 tarball은 가능한 한 보존하세요.

SDK 내부 파일을 직접 수정하거나 호스트 프로젝트에 SDK 구현을 복사하지 마세요.

## 3. v0.5.15 안내창 배치 개선 검증

v0.5.15에서는 공통 SDK의 안내창 배치 기준이 변경됐습니다.

주요 변경 내용:

1. 등록된 업무 버튼을 안내창 배치 금지 영역으로 처리
2. 겹침 면적이 작다는 이유만으로 충돌 위치를 허용하지 않음
3. 화면·안내 내용 변경 후 위치 재측정
4. 실제 브라우저 hit-test 확인
5. 안전한 위치가 없으면 안내창을 숨기고 진단 기록

무인민원발급기에서도 이 기능이 정상 작동하는지 확인하세요.

### 특히 보호할 요소

- 숫자 키패드의 0~9 버튼
- 입력값 표시 영역
- 지우기·확인 버튼
- 발급 옵션 선택 버튼
- 발급 부수 증감·선택 버튼
- 결제 버튼
- 뒤로 가기
- 처음으로
- 체험 종료
- QR 도크 및 스크롤 조작

실제 화면에 존재하는 요소를 기준으로 확인하고, 존재하지 않는 버튼을 가정하지 마세요.

기존 SDK 공개 어댑터를 통해 주요 업무 버튼이 올바르게 등록됐는지도 확인하세요.

등록이 누락된 요소가 있다면 **공개 API를 이용한 정상적인 등록 보완만 허용**합니다.

호스트별 안내창 위치 하드코딩이나 CSS 우회는 금지합니다.

## 4. Development 접근성 체험 기능 유지

현재 첫 화면에는 Development 전용 **'접근성 체험하기'** 버튼이 구현돼 있습니다.

기존 체험 기능을 변경하거나 다시 만들지 마세요.

체험 프로필은 다음 값이 유지되어야 합니다.

- textSize: extraLarge
- buttonSize: large
- contrast: high
- easyLanguage: true
- viewportMode: bottom 60%
- smartGuide: true
- guideDelaySeconds: 10
- voiceGuidance: false
- language: ko
- stepByStepGuidance: false
- conciseGuidance: false
- slowGuidance: true

특히 실제 `textSize`가 `extraLarge`인지 확인하세요.

'큰 글씨'라고 표시되는 것만 확인하지 말고 SDK 내부 적용값을 확인해야 합니다.

## 5. 쉬운 말·스마트 길잡이 검증

기존 4개 업무 단계의 안내를 유지합니다.

1. 숫자 키패드 입력
2. 발급 옵션
3. 발급 부수
4. 결제

확인할 동작:

- 쉬운 말 설명 표시
- 설명 여러 개일 때 이전·다음
- 접기·펼치기
- 스마트 길잡이 시작 전 10초 대기
- 스마트 길잡이 표시 후 15초 카운트다운
- 종료 후 기존 쉬운 말 설명으로 복귀
- 이전 설명 페이지 유지
- 접힌 상태 유지
- 단계 변경 시 이전 안내 제거
- 오래된 타이머가 새 단계에 영향을 주지 않음

`guideDelaySeconds`와 `slowGuidance`는 서로 독립적으로 처리되어야 합니다.

## 6. 화면 크기와 하단 조작 검증

다음 화면 크기를 테스트하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

하단 조작 설정:

- 60%
- 70%
- 80%

가장 중요한 조합은 **320×844 + 하단 60% + 쉬운 말 + 스마트 길잡이 + 매우 큰 글씨 + 큰 버튼**입니다.

각 조합에서 다음을 확인하세요.

- 안내창과 주요 버튼의 실제 사각형 충돌 여부
- 안내창의 hit-test에 따른 실제 클릭 차단 여부
- 키패드 버튼 클릭 가능 여부
- 입력값 확인 가능 여부
- 세로 스크롤 가능 여부
- 뒤로 가기 및 체험 종료 가능 여부
- 가로 넘침 여부

단순 캡처뿐 아니라 실제 브라우저 포인터로 버튼을 클릭해 확인하세요.

안내창이 안전한 위치를 찾지 못해 숨겨진다면 **해당 단계·화면 크기·접근성 조합과 숨김 횟수**를 기록하세요.

무조건 안내창을 보이게 하려고 업무 버튼을 가려서는 안 됩니다.

## 7. 전체 민원발급 회귀

Development 전용 접근성 체험 프로필을 적용하고 다음 과정을 실제 브라우저에서 진행하세요.

1. 첫 화면에서 접근성 체험하기 클릭
2. 증명서 선택
3. 가상 숫자로 키패드 입력
4. 지문 확인 시뮬레이션
5. 발급 옵션 선택
6. 발급 부수 선택
7. 결제 시뮬레이션
8. 발급·인쇄 진행
9. 완료 화면 확인
10. 15초 자동 복귀
11. QR 접근성 설정 초기화
12. 체험 버튼과 기존 메뉴 복원

실제 개인정보를 입력하지 말고 테스트용 가상 값만 사용하세요.

중간에 다음 조작도 확인하세요.

- 이전 단계로 돌아가기
- 단계 재진입
- 체험 종료
- 완료 시간 연장
- 수동 처음으로 돌아가기

업무 로직은 변경하지 마세요.

## 8. QR v1~v4 호환성

다음 사항을 확인하세요.

- v1 QR 모의 응답
- v2 QR 모의 응답
- v3 QR 모의 응답
- v4 QR 모의 응답
- 기존 글씨·버튼·고대비 설정
- v3/v4 하단 조작 60/70/80%
- v4 신규 언어 및 안내 선호값 보존
- 세션 종료 후 기본값 복귀

중앙 QR Production은 아직 v4로 재배포하지 않았으므로, 실제 중앙 API에서 v4 응답이 온다고 가정하지 마세요.

이번 테스트는 모의 프로필과 Development 체험 기능을 이용합니다.

## 9. Production 체험 기능 비노출

기존 Development 전용 기능이 유지되는지 확인하세요.

- Production 빌드에서 접근성 체험하기 버튼 비노출
- Production에서 체험 프로필 적용 불가
- URL 파라미터로 개발용 체험 기능 활성화 불가
- 기존 QR 스캔과 일반 업무는 정상 동작
- 개발용 UI가 실제 배포 화면에 남지 않음

Production 서버와 DB를 변경하지 마세요.

Publish도 하지 마세요.

## 10. 문제 발생 시 처리 원칙

SDK v0.5.15 적용 후에도 주요 버튼 겹침이 발생한다면 다음을 확인하세요.

- 해당 요소의 SDK 등록 상태
- 안내창과 버튼 위치
- 브라우저 hit-test 결과
- 화면 크기 및 하단 조작 비율
- 스마트 길잡이 또는 쉬운 말 안내 여부
- 안내창이 재배치되는 시점

**공통 SDK 문제라면 무인민원발급기 안에서 임시 CSS나 자체 배치 로직으로 우회하지 마세요.**

재현 가능한 조건을 보고하고, 데모커피의 SDK 원본에서 후속 수정할 수 있도록 정리하세요.
