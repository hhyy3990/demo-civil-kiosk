# 내 방식 QR — 무인민원발급기 QR 도크 하단 모드 동기화 및 165px 중복 여백 해결

현재 무인민원발급기 프로젝트에는 공통 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.5`가 설치되어 있습니다.

직전 진단에서 360×667 화면의 마지막 증명서 메뉴가 스크롤 최하단에서 사라지는 원인을 확인했습니다.

**원인: QR 프로필의 viewportMode는 SDK에 적용되지만, QR 도크에는 bottomViewportPercent가 전달되지 않아 도크가 일반 모드의 여백을 계속 예약하는 연결 불일치입니다.**

이번 작업은 SDK 내부를 수정하지 않고, 무인민원발급기 호스트의 SDK 연결 코드만 최소한으로 수정해 해결하는 것입니다.

향후 공통 SDK v0.5.6 이상을 개발할 때는 QR 도크의 하단 모드를 SDK 내부에서 자동 동기화할 예정입니다. 따라서 지금은 공개 API를 활용한 최소 연결 수정만 진행합니다.

## 1. 기존 원인과 측정값

기존 진단 결과:

- 실제 스크롤 영역: `<main class="stage">`
- QR 도크 높이: 72px
- 고정 하단 조작부 높이: 약 93px
- SDK `.stage::after` 예약 공간: 165px
- 하단 viewport에도 이미 165px inset 반영
- 중복 예약으로 마지막 메뉴 뒤에 과도한 스크롤 여백 발생

360×667에서 측정한 값:

| 하단 모드 | 표시 영역 높이 | 기존 추가 공간 |
|---|---:|---:|
| 60% | 301px | 165px |
| 70% | 351px | 165px |
| 80% | 401px | 165px |

개발용 하단 viewport 시험 경로에서는 `createQrEntryDock()`에 `bottomViewportPercent`를 전달해 `.a11y-qr-entry-dock-bottom` 클래스가 적용됐고, `::after` 높이와 실제 scrollHeight 기여가 0px이 됐습니다.

반면 QR 프로필 적용 경로에서는 해당 옵션을 도크에 전달하지 않았습니다.

이번에는 이 두 경로를 일치시켜 주세요.

## 2. 수정 전 구조 확인

먼저 `src/useKioskAccessibility.ts`를 분석합니다.

확인 사항:

- SDK 인스턴스 생성과 유지 방식
- createQrEntryDock() 호출 위치
- 개발용 viewport 모드 적용 경로
- QR 프로필 applyProfile() 호출 경로
- 현재 적용 중인 viewportMode 상태
- 도크 생성·제거·재생성 조건
- QR 모달의 열림 상태와 닫힘 처리
- 화면 전환 notifyScreenChange()
- 세션 종료 endSession()

현재 코드를 확인한 후 **기존 공개 API를 이용하는 가장 작은 수정 방법**을 선택해 주세요.

## 3. QR 프로필과 도크 하단 모드 동기화

QR v3 프로필에 다음 값이 있을 수 있습니다.

- `viewportMode: null`
- `viewportMode: { mode: "bottom", heightPercent: 60 }`
- `viewportMode: { mode: "bottom", heightPercent: 70 }`
- `viewportMode: { mode: "bottom", heightPercent: 80 }`

이 값이 SDK의 실제 하단 viewport에 적용되는 동시에 QR 도크에도 정확히 반영되어야 합니다.

연결 원칙:

1. QR 프로필 적용이 성공한 뒤 실제 적용된 viewportMode를 기준으로 도크 설정을 동기화합니다.
2. 개발용 하단 viewport 시험 경로와 QR 프로필 경로에서 동일한 도크 모드 처리 방식을 사용합니다.
3. null이면 도크도 일반 모드로 복원합니다.
4. 60·70·80%가 서로 변경되면 해당 값으로 반영합니다.
5. QR v1/v2 프로필은 기존 정책대로 하단 모드를 자동 활성화하지 않습니다.
6. 활성 프로필의 다른 접근성 설정은 유지합니다.
7. 모드가 변하지 않았다면 불필요하게 도크를 다시 생성하지 않습니다.

**QR 프로필의 저장된 설정을 직접 변경하거나, SDK의 applyProfile()을 우회하지 마세요.**

SDK의 하단 viewport 자동 적용은 그대로 유지해야 합니다.

## 4. 도크 재생성이 필요한 경우

현재 SDK v0.5.5의 QR 도크 컨트롤러에는 bottomViewportPercent를 변경하는 setter가 없는 것으로 확인됐습니다.

따라서 기존 공개 API로 동적 업데이트가 불가능하다면, 모드 변경 시에만 도크를 안전하게 재생성하는 방식을 사용할 수 있습니다.

다만 다음 조건을 반드시 지켜 주세요.

- 기존 도크 DOM 및 이벤트 리스너 정리
- SDK가 제공하는 destroy/cleanup 계약 준수
- 동일 도크가 두 개 생성되지 않음
- QR 스캐너 중복 실행 없음
- QR 모달이 열려 있는 도중 불필요하게 재생성하지 않음
- QR 모달을 닫고 프로필 적용이 끝난 뒤 정상 전환
- QR 수동 입력 기능 유지
- QR 카메라 스캔 기능 유지
- QR 도크의 active 상태 유지
- 도크 생성에 필요한 callback 및 root 정보 유지
- 모드 변경 시 viewport 높이 재측정
- 모달 열림 상태와 이벤트 리스너 누수 없음

가능한 경우 기존 도크 컨트롤러를 재사용하고, 불가능한 경우에만 재생성합니다.

**React 재렌더링마다 도크를 제거하고 다시 만드는 방식은 금지합니다.**

## 5. 화면별 QR 도크 정책 유지

기존 정책은 다음과 같습니다.

- 첫 화면에서는 QR 도크 표시
- 업무 진행 화면에서는 QR 도크 숨김
- 발급 완료 후 처음화면 복귀 시 QR 도크 표시
- 세션 종료 후 접근성 프로필 초기화
- 첫 화면 복귀 시 일반 모드 복원

이번 수정으로 다음 문제가 생기면 안 됩니다.

- 업무 화면에서 QR 도크가 다시 나타남
- QR 설정 버튼이 여러 개 생김
- 처음화면에서 QR 도크가 사라짐
- 업무 도중 접근성 설정이 초기화됨
- 발급 종료 후 이전 사용자의 프로필이 남음

## 6. 165px 예약 공간 검증 — 핵심

360×667에서 다음 상태를 검사합니다.

- QR 미적용
- v3 viewportMode null
- 하단 60%
- 하단 70%
- 하단 80%
- 60% → 70% → 80% 프로필 교체
- 하단 모드 → null 프로필 교체
- 발급 업무 진입
- 처음화면 복귀

측정 항목:

- `.stage::after` computed height
- 실제 scrollHeight 기여량
- scrollArea 높이
- document.scrollTop
- SDK viewport top/bottom
- QR 도크 실제 표시 여부
- QR 도크 active 상태
- 고정 조작부와의 겹침 여부

**합격 기준: 하단 viewport가 적용된 상태에서 개발용 정상 경로와 동일하게 불필요한 165px 예약 공간이 제거되어야 합니다.**

단, QR 도크나 고정 버튼을 위한 실제 안전 영역이 사라져 콘텐츠가 가려지면 실패입니다.

기본 모드에서 필요한 예약 공간은 기존대로 유지합니다.

## 7. 마지막 증명서 메뉴 실제 접근성

360×667에서 하단 60·70·80%를 각각 검사합니다.

절차:

1. 큰 글씨·큰 버튼·고대비 모의 QR 적용
2. 실제 휠 또는 Chromium 터치 시뮬레이션으로 최하단까지 스크롤
3. 마지막 증명서 메뉴 전체 표시 확인
4. 중앙 및 네 모서리 hit-test
5. 실제 클릭
6. 데모 안내 표시 확인
7. 100ms·500ms·1초·3초 스크롤 위치 안정성 확인
8. 위로 돌아가면 제목이 보이는지 확인

최하단에서 마지막 메뉴가 여전히 가려진다면, 남은 여백을 다시 분석하고 원인이 호스트 연결인지 SDK 공통 문제인지 보고해 주세요.

다른 CSS를 추가로 덮어써서 억지로 해결하지 마세요.

## 9. 화면 전환 API 회귀

기존 notifyScreenChange() 연동은 변경하지 않습니다.

검증할 내용:

- 증명서 선택 후 새 화면 상단 표시

- 처음화면 복귀 시 상단 표시
- 같은 화면의 입력값 변경 시 스크롤 유지
- QR 모달 열기·닫기 시 스크롤 유지
- 화면 변경 후 사용자의 직접 스크롤 보존
- QR 도크 재생성 후 화면 전환 정상

화면 전환 시 별도의 scrollTo 타이머를 추가하지 마세요.

## 10. 스마트 길잡이와 스크롤 안내 회귀

다음을 확인합니다.

- 스마트 길잡이 10·15·20초 지연
- 단계별 안내 유지
- 음성 안내 설정 유지
- 스크롤 안내 시작·중간 표시
- 최하단에서 안내 숨김
- 위로 이동하면 다시 표시
- 숨겨진 안내는 클릭 방해 없음
- 숨겨진 안내는 스크린리더에서 제외
- 세션 종료 후 안내 상태 초기화

SDK v0.5.5의 스크롤 안내 DOM 재사용 구조를 변경하면 안 됩니다.

## 11. QR 프로필 호환 및 전체 발급 흐름

QR v1/v2/v3 모의 응답을 확인합니다.

- v1/v2의 기존 데이터 정상 처리
- v1 simplifiedLayout은 무시
- v2 bottomControls는 방법 B로 자동 전환하지 않음
- v3 viewportMode 정상 적용

390×844, 하단 80% 상태에서 전체 발급 흐름을 수행합니다.

1. 주민등록등본 선택
2. 임의 13자리 입력
3. 지문 확인 시뮬레이션
4. 발급 옵션 선택
5. 수수료 면제
6. 2부 선택
7. 신청 내용 확인
8. 가상 카드 결제
9. 인쇄 중
10. 발급 완료
11. 처음화면 복귀
12. 프로필 초기화
13. QR 도크 정상 재표시

실제 주민번호나 결제정보는 사용하지 않습니다.
