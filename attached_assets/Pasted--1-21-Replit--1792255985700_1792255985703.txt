# 무인민원발급기 — 쉬운 말 안내 1/21 과분할 재현 및 원인 측정

현재 프로젝트는 **무인민원발급기 Replit**입니다.

이번 작업은 사용자가 실제 화면에서 발견한 쉬운 말 안내의 비정상적인 페이지 분할 문제를 재현하고 원인을 확인하는 **진단 전용 작업**입니다.

**코드, CSS, SDK, 안내 문구, 설정 정책, tarball을 수정하지 마세요. Publish도 금지합니다.**

## 1. 실제 사용자 오류

주민등록표 종류 선택 화면에서 사용자가 다음 현상을 확인했습니다.

- stepId: `certificate.type-selection`
- 안내 제목: `주민등록표 등본`
- 페이지 표시: `1/21`
- 첫 페이지 본문: `주민등록표`
- 이후 페이지도 한 단어 또는 짧은 표현씩 분할됨

이는 원문이 모두 보존되더라도 사용자 입장에서 정상적인 안내가 아닙니다.

기존 SDK 테스트에서 원문 보존과 잘림 없음이 통과됐다는 이유만으로 문제없다고 판단하지 마세요.

## 2. 정확한 재현 설정

먼저 실제 사용자 화면과 동일한 조합을 재현하세요.

- 화면 크기: 390×844부터 시작
- textSize: extraLarge
- buttonSize: large
- contrast: high
- easyLanguage: true
- smartGuide: true
- viewportMode: null
- slowGuidance: false

`viewportMode: null` 상태에서 쉬운 말이 켜져 있으면 SDK가 **자동 하단 80%**를 적용해야 합니다.

이 설정에서 증명서 종류 선택 화면을 열고 쉬운 말 안내를 확인하세요.

이후 다음 조건도 비교하세요.

- 명시적 하단 80%
- DEV 체험 하단 60%
- 360×667 자동 하단 80%
- 320×844 자동 하단 80%

가능하면 실제 사용자가 적용했던 QR v4 프로필과 동일한 설정으로 재현하되, Production DB에 프로필을 새로 만들거나 기존 데이터를 수정하지 마세요.

합성 QR 응답을 사용할 경우 실제 Production QR 테스트라고 주장하지 마세요.

## 3. 쉬운 말 안내 원문

현재 호스트가 전달하는 실제 데이터는 다음과 같습니다.

stepId: `certificate.type-selection`

첫 번째 항목:
- title: `주민등록표 등본`
- text: `주민등록표 등본은 한 세대의 구성과 주소 정보를 확인하는 주민등록 서류입니다.`

두 번째 항목:
- title: `주민등록표 초본`
- text: `초본 발급은 아직 준비 중입니다. 이 데모에서는 등본만 진행할 수 있습니다.`

실제 호스트 코드와 다시 대조하고, 현재 데이터가 같으면 그대로 사용하세요.

문구를 축약하거나 변경하지 마세요.

## 4. 페이지 분할 상세 측정

각 화면 크기·모드에서 다음 정보를 기록하세요.

1. 실제 적용된 viewportMode와 하단 작업 영역 비율
2. 패널 전체 최대 높이 및 실제 높이
3. 헤더 높이
4. 이전·다음 버튼과 페이지 번호가 차지하는 공간
5. 본문 영역의 clientHeight, scrollHeight
6. 본문 font-size 및 line-height
7. SDK가 분할 계산에 사용한 가용 높이
8. 실제 한 줄에 필요한 높이
9. 전체 페이지 수
10. 각 페이지에 표시되는 본문 원문
11. 페이지 이동 시 전체 페이지 수가 달라지는지
12. 페이지 이동 직후 레이아웃이 다시 측정되는지
13. 패널 상단 Y 좌표
14. 페이지 이동 시 업무 화면 스크롤 위치 변화 여부
15. 콘솔의 SDK 페이지 분할 관련 경고

특히 **한 줄 높이가 본문 가용 높이보다 큰지** 확인하세요.

예전에 SDK 로그에서 다음과 같은 값이 관찰됐습니다.

- 본문 가용 높이: 약 30px
- 한 줄 최소 높이: 약 31px

이번 오류에서도 같은 상황이 발생하는지 확인해야 합니다.

## 5. 1/21 또는 비슷한 과분할이 재현되면

다음 항목을 추가로 확인하세요.

- 첫 페이지에 정말 `주민등록표`만 표시되는지
- 페이지별 텍스트가 단어 단위로 분리되는지
- 페이지 수가 21개로 고정되는지, 이동할 때 달라지는지
- 쉬운 말 항목 제목이 바뀔 때 페이지 수가 다시 계산되는지
- 이전·다음 버튼 표시가 본문 공간에 영향을 미치는지
- 접기·펼치기 후 페이지 수가 바뀌는지
- 스마트 길잡이 실행 전후 페이지 수가 바뀌는지

분할 결과의 원문 보존 여부도 확인하되, 한 단어씩 분할되는 현상은 별도로 실패로 기록하세요.

## 6. 재현되지 않는 경우

1/21이 나타나지 않더라도 다음을 확인하세요.

- 자동 하단 80%가 실제 적용됐는지
- DEV 하단 60%와 혼동하지 않았는지
- 최신 SDK JS/CSS가 로드됐는지
- QR 모달을 닫은 후 실제 안내가 다시 설정됐는지
- 사용자 스크린샷과 테스트 화면의 패널 높이가 같은지
- 사용자가 본 화면과 현재 Preview의 CSS/브라우저 상태 차이가 있는지

정확히 재현되지 않았는데 임의로 SDK 오류 원인을 단정하지 마세요.

필요하다면 화면 크기와 접근성 설정을 바꾸며 최소 재현 조건을 찾되, 새로운 기능이나 테스트용 UI를 추가하지 마세요.
