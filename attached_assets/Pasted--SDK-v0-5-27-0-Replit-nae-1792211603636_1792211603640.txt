# 무인민원발급기 — 공통 SDK v0.5.27 설치 및 전체 회귀 검증

## 0. 작업 대상과 원칙

현재 프로젝트는 **무인민원발급기 Replit**입니다.

첨부한 `naebangsik-kiosk-accessibility-sdk-0.5.27.tgz`를 사용해 기존 공통 SDK v0.5.26을 **v0.5.27로 업데이트**해 주세요.

패키지명: `@naebangsik/kiosk-accessibility-sdk`

이번 작업의 목적은 다음 두 가지뿐입니다.

1. v0.5.26에서 발견된 하단 조작 모드 변경 시 쉬운 말 자동 페이지 재분할 오류가 해결됐는지 확인
2. 이전에 중단했던 QR v1~v4 및 전체 민원발급 회귀 검증 완료

**사용자가 요청하지 않은 새로운 기능·디자인·안내 문구·동작 방식은 절대 추가하거나 변경하지 마세요.**

새로운 수정이 필요하면 원인과 변경 범위를 먼저 보고하고 사용자 승인을 기다려 주세요.

SDK-first 원칙을 지켜 주세요. 공통 SDK 문제는 데모커피 프로젝트의 SDK 원본에서 수정해야 합니다.

## 1. SDK 설치

먼저 현재 설치된 SDK가 v0.5.26인지 확인하세요.

이후 첨부된 공식 tarball을 설치합니다.

- 패키지명 및 버전 v0.5.27 확인
- package.json, package-lock.json 갱신
- 기존 v0.5.26 tarball 보존
- 설치 패키지의 무결성 확인
- 실제 브라우저 런타임에서도 v0.5.27이 로드되는지 확인
- SDK 내부 소스 및 호스트 업무 코드 변경 금지
- 타입 검사와 프로덕션 빌드 실행

개발 서버에 이전 SDK 번들이 캐시되어 있다면 기존 프로젝트의 정상적인 빌드·재시작 과정으로 갱신하고, 실제 런타임 버전을 확인하세요.

## 2. 자동 페이지 재분할 오류 검증 — 최우선

v0.5.26에서는 다음 오류가 발견됐습니다.

320×844 화면에서 긴 쉬운 말 안내를 표시한 상태로 일반 화면에서 하단 80% 모드로 전환하면, 안내창 높이는 줄어들지만 이전 페이지 분할을 그대로 사용하여 본문과 이전·다음 버튼이 잘렸습니다.

v0.5.27에서는 `setViewportMode()` 호출 시 SDK가 자동으로 재분할하도록 수정했습니다.

### 테스트 조건

- 화면 크기: 320×844
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 활성화
- 충분히 긴 테스트용 안내문
- 일반 화면 → 하단 80% 전환

다음을 실제 브라우저에서 확인하세요.

1. 일반 화면에서 긴 설명이 여러 페이지로 분할됨
2. 설명 중간 페이지로 이동
3. `setViewportMode({mode:'bottom',heightPercent:80})` 호출
4. 줄어든 가용 높이에 맞게 페이지 수 자동 변경
5. 원래 읽던 문장이 포함된 페이지 유지
6. 본문 잘림 없음
7. 이전·다음 버튼 잘림 없음
8. 페이지를 끝까지 이동하면 전체 원문 확인 가능
9. 원문 누락·중복 없음
10. 호스트에서 `setEasyLanguageState()`를 다시 호출하지 않아도 정상 작동

**이번 검증에서 기존 호스트가 안내 데이터를 반복 전달하는 우회 코드를 추가하지 마세요.**

실제 안내 문구가 짧아 분할이 일어나지 않는다면 브라우저 테스트에서만 임시 긴 문구를 주입하세요. 서비스 안내 문구는 변경하지 않습니다.

## 3. 화면 모드 전환 전체 검증

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

화면 모드:

- 일반 화면
- 하단 60%
- 하단 70%
- 하단 80%

같은 쉬운 말 설명을 표시한 상태에서 실제 모드를 전환하세요.

확인할 항목:

- 모드 변경 즉시 페이지 재분할
- 읽던 원문 위치 유지
- 페이지 이동 정상
- 원문 순서 및 전체 내용 보존
- 패널 높이 정상 제한
- 안내창 내부 스크롤 없음
- 본문 및 버튼 잘림 없음
- 접기·펼치기 상태 유지
- 브라우저 크기 변경 시 재분할 유지

모든 조합을 통과하지 못했다면 전체 검증을 완료했다고 보고하지 마세요.

## 4. 상단 안내 패널 위치 안정성

이전 사용자 테스트에서 쉬운 말 안내를 다음 페이지로 넘길 때마다 패널이 상단 영역 안에서 위아래로 이동했습니다.

v0.5.25부터 수정한 위치 안정성이 유지되는지 확인하세요.

검증 동작:

- 쉬운 말 이전·다음
- 자동 분할 페이지 이동
- 접기·펼치기
- Smart Guide 시작
- Smart Guide 종료
- 기존 쉬운 말 페이지 복원

실제 DOM 좌표를 측정합니다.

기존 기준:

- 일반 화면: 상단 약 12px
- 하단 조작 모드: 상단 약 8px

동일 화면의 안내 상태 전환 중에는 상단 위치가 바뀌지 않아야 합니다.

단, 최초 등장 애니메이션 도중의 일시적인 위치 변화와 안정화 이후의 페이지 이동 문제는 구분해서 기록하세요.

## 5. 하단 스크롤 안내 회귀 검증

기존 v0.5.24에서 해결한 동작을 유지합니다.

- 실제 스크롤 영역 하단에서 12px 위에 표시
- 아래에 볼 내용이 남아 있으면 반드시 표시
- 스크롤 중 위치 점프 없음
- 맨 아래에서는 숨김
- 다시 위로 스크롤하면 재표시
- 쉬운 말·Smart Guide와 공존
- 업무 버튼과 겹쳐도 안내 유지
- pointer-events:none으로 클릭 통과
- 모달에서는 실제 활성 모달의 스크롤 상태 반영

다음 화면에서 실제 휠·터치 스크롤을 검증하세요.

- 증명서 메뉴
- 주민등록등본 유형
- 주민등록번호 키패드
- 지문 확인
- 표시 항목 선택
- 수수료 면제
- 발급 부수
- 신청 내용 확인
- 결제
- 발급 완료

특히 390×844 하단 60%에서 스크롤 안내가 화면 중간으로 튀거나 위치를 바꾸지 않는지 실제 Y 좌표로 확인하세요.

**사용자는 스크롤 안내와 업무 버튼이 시각적으로 겹치는 것을 허용했습니다. 겹친다는 이유로 안내를 숨기거나 다른 위치로 이동시키지 마세요.**

## 6. 스마트 길잡이 회귀 검증

Development 접근성 체험 프로필 기준:

- 표시 전 대기: 약 10초
- slowGuidance 활성 시 표시 시간: 약 15초

다음을 확인하세요.

- 키패드 입력 중 조기 종료 없음
- 표시 항목 선택 중 조기 종료 없음
- 부수 변경 중 조기 종료 없음
- 스크롤 중 조기 종료 없음
- 실제 업무 단계 변경 시 이전 Smart Guide 정리
- Smart Guide는 단일 안내
- Smart Guide 표시 중 이전·다음·페이지 번호 없음
- 종료 후 기존 쉬운 말 페이지와 접힘 상태 복원
- 화면 모드 재분할 중 Smart Guide 타이머 재시작 없음

실제 표시 시작·종료 시각을 측정하세요.

## 7. 기존 접근성 UI 유지

다음 설정과 UI를 변경하지 않고 검증하세요.

- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 안내
- 스마트 길잡이
- 음성 안내
- 하단 조작 60/70/80%
- QR 도크
- 44×44px 공통 안내 조작 버튼
- 완료 후 15초 자동 복귀

쉬운 말 문구를 다시 작성하거나 기존 안내 페이지의 내용을 임의로 추가·삭제하지 마세요.

긴 쉬운 말 자동 분할은 사용자가 승인한 기존 기능이므로 그대로 유지합니다.

## 8. QR v1~v4 회귀 검증

v0.5.26에서 SDK 결함 발견으로 중단됐던 검증입니다.

기존 QR 적용 경로에 브라우저 모의 응답을 사용하여 다음을 확인하세요.

- v1 QR 프로필
- v2 QR 프로필
- v3 QR 프로필
- v4 QR 프로필
- 일반 화면 및 하단 조작 모드 적용
- QR 설정 확인 모달
- 확인 버튼 실제 클릭
- 모달이 열린 동안 뒤쪽 안내 패널이 조작을 방해하지 않음
- 모달을 닫은 뒤 기존 안내 복원
- QR 도크 정상 표시
- 세션 종료 후 접근성 설정 초기화
- 이후 다른 QR 프로필 재적용 가능

모의 QR 토큰은 SDK가 요구하는 최소 길이 조건을 충족하도록 사용하세요.

실제 중앙 QR API 호출과 카메라 하드웨어 검증은 이번 범위에 포함하지 않습니다.

## 10. 오류 발견 시 대응

SDK-first 원칙을 반드시 지킵니다.

공통 SDK 문제라면 무인민원발급기 호스트에서 수정하지 마세요.

다음 정보를 보고하세요.

- 발생 화면 및 조건
- SDK 버전
- 적용한 접근성 프로필
- 실제 DOM 위치와 크기
- 오류 재현 순서
- SDK와 호스트 연결 중 원인 구분
- 데모커피 공통 SDK에서 수정해야 할 사항

그런 오류가 발견되면 추가 기능이나 임시 우회를 만들지 말고 해당 검증을 중단하세요.

호스트 연결 문제라도 이번 요청 범위를 넘어서는 수정이 필요하면 먼저 보고하고 사용자 승인을 기다리세요.
