# 무인민원발급기 — 공통 SDK v0.5.10 설치 및 스마트 길잡이·스크롤 안내 실사용 검증

현재 프로젝트는 무인민원발급기 시뮬레이션입니다.

현재 설치된 공통 SDK는 v0.5.8이며, 데모커피 프로젝트에서 제작한 v0.5.10 tarball을 업로드했습니다.

이번 작업 목표는 다음과 같습니다.

1. SDK v0.5.10 설치
2. 하단 60·70·80%에서 스마트 길잡이가 실제로 나타나는지 확인
3. 표시된 스마트 길잡이가 **10초 후 자동으로 사라지는지 확인**
4. 첫 화면을 포함한 모든 주요 업무 화면에서 스크롤 안내가 정상 작동하는지 확인
5. 기존 접근성 및 민원발급 기능 유지

**SDK 우선 원칙:** 호스트 전용 팝업, 타이머, 스크롤 안내를 새로 만들지 않습니다. 공통 SDK에서 제공하는 기능을 그대로 사용하고, 결함이 있다면 원인을 보고해 주세요.

## 1. SDK 설치

업로드된 `naebangsik-kiosk-accessibility-sdk-0.5.10.tgz`의 위치와 메타데이터를 확인하세요.

- name: `@naebangsik/kiosk-accessibility-sdk`
- version: `0.5.10`

확인 후 기존 v0.5.8을 교체합니다.

- package.json, lockfile 업데이트
- 실제 설치 모듈 버전 검증
- 기존 v0.5.8 tarball 보존
- SDK 공개 API 및 타입 호환성 확인
- Vite 캐시 때문에 구 SDK가 사용되지 않도록 확인

## 2. 스마트 길잡이 표시 테스트

다음 네 화면에서 실제 표시 여부를 확인합니다.

- 주민등록번호 키패드 입력
- 증명서 표시 항목 선택
- 발급 부수 입력
- 결제 방법 선택

각 화면에서 다음 조건을 테스트합니다.

- 기본 모드
- QR v3 하단 60%
- QR v3 하단 70%
- QR v3 하단 80%

특히 **360×667 + 하단 60%**를 중점적으로 확인합니다.

각 화면에 진입한 후 설정된 대기 시간이 지나면 스마트 길잡이가 화면에 보여야 합니다.

공간이 부족해서 다른 일반 버튼과 잠시 겹치는 것은 허용합니다.

다만 안내가 화면 밖으로 잘리거나 아예 나타나지 않는 현상은 실패로 기록하세요.

## 3. 스마트 길잡이 자동 닫힘

v0.5.10의 기존 구현대로 다음을 확인합니다.

- 안내 표시 전 10·15·20초 지연 유지
- 표시된 시점부터 약 10초 후 자동 닫힘
- 자동 닫힘 시 버튼 강조 함께 제거
- 자동 닫힘 후 버튼 조작 정상
- 같은 업무 단계에서 값만 바뀌어도 재등장하지 않음
- 사용자가 직접 닫으면 즉시 사라짐
- 다른 화면으로 이동하면 이전 안내 즉시 제거
- 처음화면 복귀 및 endSession() 후 재등장하지 않음

**호스트에서 별도 10초 타이머를 추가하지 마세요.**

SDK의 자동 닫힘을 그대로 사용해야 합니다.

## 4. 스크롤 안내 전체 업무 화면 검증

SDK의 안내 문구인 **'↓ 아래에도 내용이 있어요'**를 확인합니다.

다음 화면을 각각 점검합니다.

- 증명서 18개 선택 화면
- 주민등록번호 입력
- 지문 확인 시뮬레이션
- 증명서 표시 항목 선택
- 수수료 확인
- 발급 부수 선택
- 결제 방법 선택
- 인쇄 중
- 발급 완료

각 화면에서 다음을 구분합니다.

1. 실제로 아래에 콘텐츠가 더 있는가?
2. 사용자가 실제로 스크롤할 수 있는가?
3. 스크롤 안내가 표시되는가?
4. 최하단으로 스크롤하면 사라지는가?
5. 다음 화면으로 넘어가면 새 스크롤 상태를 기준으로 다시 계산하는가?

스크롤할 필요가 없는 화면에서 안내가 나타나지 않는 것은 정상입니다.

반면 실제로 아래에 콘텐츠가 남아 있는데 안내가 표시되지 않으면 문제로 기록합니다.

큰 글씨·큰 버튼·하단 60·70·80%에서도 검증합니다.

## 5. 진단 방식

스크롤 안내가 나타나지 않으면 다음을 측정합니다.

- 현재 화면 ID
- 활성 스크롤 컨테이너
- scrollTop
- scrollHeight
- clientHeight
- 실제 스크롤 가능 여부
- SDK 안내 요소의 존재 여부
- 안내 요소의 화면상 좌표
- 안내 요소의 visibility 및 display 상태
- QR 도크·하단 고정 버튼과의 위치 관계

스크롤이 가능한데도 안내가 보이지 않으면 SDK 판정 문제인지, 잘못된 호스트 영역 연결인지 구분해 보고하세요.

단, SDK 내부 코드를 수정하거나 호스트에 별도 스크롤 안내를 만들지 마세요.

## 6. 화면 크기별 검증

- 320×844
- 360×667
- 390×844
- 1080×1920
- 1440×900
- 1920×1080

모든 화면 크기에서 모든 조합의 장시간 타이머 검증이 어렵다면, 주요 조합을 우선하고 실제로 검증한 범위를 명시하세요.

기존 사용자가 직접 확인한 글씨 크기 및 QR 도크의 시각적 배치는 임의로 변경하지 않습니다.

## 7. 전체 발급 흐름

초기 화면 → 증명서 선택 → 주민등록표 등본 → 가상 숫자 입력 → 지문 확인 → 표시 항목 선택 → 수수료 확인 → 발급 부수 → 결제 방법 → 모의 결제 → 인쇄 중 → 발급 완료 → 처음 화면

다음 기존 기능을 유지합니다.

- 증명서 메뉴 18개
- QR v1/v2/v3
- 스마트 길잡이 stepId
- 큰 글씨·매우 큰 글씨
- 큰 버튼·고대비
- QR 도크 자동 동기화
- 선택적 5~10% 글씨 보정
- 개발자용 레이아웃 진단
- 스크롤 위치 초기화
- 세션 종료 후 설정 초기화

실제 개인정보 대신 테스트용 값을 사용합니다.
