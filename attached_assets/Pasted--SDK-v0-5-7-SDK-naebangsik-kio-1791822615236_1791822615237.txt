# 무인민원발급기 — 공통 SDK v0.5.7 설치 및 하단 안내문 자동 보정 검증

현재 프로젝트는 무인민원발급기 시뮬레이션입니다.

기존 SDK는 `@naebangsik/kiosk-accessibility-sdk@0.5.6`이며, 새로 업로드한 `naebangsik-kiosk-accessibility-sdk-0.5.7.tgz`를 설치하려고 합니다.

이번 작업의 핵심은 **큰 글씨 모드를 유지하면서 하단의 두 안내 문구에 5~10% 자동 보정을 적용하고, 실제 겹침이 얼마나 해결되는지 확인하는 것**입니다.

## 1. SDK v0.5.7 설치

- 업로드된 tarball의 실제 위치 확인
- 패키지명과 버전 확인
- 기존 v0.5.6을 v0.5.7로 교체
- package.json, lockfile, 설치된 모듈 버전 확인
- 기존 v0.5.6 tarball 보존
- 공개 API와 타입 선언 호환성 확인

패키지가 없거나 메타데이터가 다르면 임의로 재구현하지 말고 중단하세요.

## 2. 두 안내 문구 모두 보정 대상으로 등록

현재 하단에는 다음 문구가 있습니다.

- 민원 발급 시뮬레이션
- 실제 신청 정보는 저장되지 않습니다

기존에는 첫 번째 문구만 `getFontCorrectionTargets()`에 등록되어 있었습니다.

이번에는 **두 문구 모두 보정 대상으로 등록**해 주세요.

개인정보 안내라는 이유만으로 두 번째 문구를 제외하지 않습니다.

다만 실제 주민등록번호, 입력값, 인증번호, 결제정보 등 민감한 데이터는 보정 대상이나 진단 로그에 포함하지 마세요.

다음 조건은 반드시 유지합니다.

- 큰 글씨 모드 자체는 유지
- 매우 큰 글씨 모드 유지
- 기본 확대 비율 유지
- 문제가 있을 때만 5% 축소 시도
- 필요하면 최대 10% 축소
- 10% 초과 축소 금지
- 겹침이 해결되지 않으면 원래 글씨 크기로 복원
- 문제가 없는 문구는 축소하지 않음
- 주요 업무 버튼 및 증명서 메뉴는 자동 축소하지 않음

## 3. 기존 진단 결과와 비교

이전 360×667 브라우저 실험에서 다음 결과가 확인됐습니다.

- 14px에서 두 문구를 모두 10% 축소하면 12.6px로 변경되고 조작부 겹침이 사라짐
- 16px에서 두 문구를 모두 10% 축소하면 14.4px이지만 약 4px 겹침이 남음

이번에는 SDK v0.5.7의 실제 자동 보정 기능으로 같은 현상이 발생하는지 검사합니다.

특히 다음을 기록하세요.

- 보정 전 크기
- 5% 축소 시 실제 크기
- 10% 축소 시 실제 크기
- SDK의 최종 선택
- 보정 유지 또는 복원 여부
- 최종 조작부 겹침 px
- QR 도크 실제 버튼과 겹침 px

**SDK가 실패했다고 해서 다시 최소 글씨 크기 제한을 추가하지 마세요.**

## 4. 개발자 레이아웃 진단

`inspectLayout()`과 실제 DOM 좌표를 비교하세요.

확인 항목:

- 두 안내 문구의 실제 위치
- 고정 홈·전화면 버튼의 실제 위치
- 안내문과 버튼의 겹침 여부
- QR 도크의 장식 영역과 실제 QR 버튼 구분
- 푸터 부모·자식 관계로 인한 오탐 여부
- 고정 높이 컨테이너 밖으로 문구가 넘치는지
- 문제가 없는데 오류로 판정하는 사례
- 실제 문제가 있는데 놓치는 사례

SDK 진단 결과만으로 판단하지 말고 실제 브라우저에서 위치와 가림을 확인하세요.

## 5. 실제 사용 화면 검증

다음 화면 크기에서 테스트합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920
- 1440×900
- 1920×1080

각 화면에서 다음 프로필을 적용합니다.

- 기본
- 큰 글씨
- 매우 큰 글씨
- 큰 버튼
- 큰 글씨 + 하단 60·70·80%
- 매우 큰 글씨 + 하단 60·70·80%

특히 360×667에서 큰 글씨와 매우 큰 글씨 결과를 집중 확인하세요.

다음 항목도 반드시 확인합니다.

- 18개 증명서 메뉴 유지
- 첫 메뉴 및 마지막 메뉴 접근 가능
- 마지막 메뉴 실제 클릭 성공
- 홈·전화면 버튼 클릭 가능
- QR 도크 중복 생성 없음
- QR 도크 하단 모드 자동 동기화 유지
- 스크롤 위치 정상
- 고대비·큰 버튼 정상 작동
- 화면 전환 시 SDK 설정 정상 유지
- 세션 종료 시 원래 상태 복원

## 6. 14.4px에서 겹침이 남는 경우

**이번에는 추가 공간 보정이나 푸터 재배치를 구현하지 마세요.**

이전 측정에서 매우 큰 글씨를 14.4px로 줄여도 약 4px 겹침이 남았습니다.

이번 실제 SDK 적용에서도 문제가 남는다면 다음을 보고하세요.

- 최종 보정이 유지됐는지 원복됐는지
- 14.4px 상태의 실제 겹침 위치
- 조작 버튼의 글자를 가리는지
- 안내 문구 일부가 실제로 가려지는지
- 터치·클릭 영역에 영향을 주는지
- 겹침이 발생하는 화면과 프로필 조합

문제가 남더라도 10%를 초과해 축소하거나 CSS를 임의로 고치지 마세요.

사용자가 실제 화면을 보고 후속 수정을 결정할 예정입니다.

## 7. 전체 발급 흐름 회귀

초기 화면 → 증명서 선택 → 주민등록표 등본 → 가상 숫자 입력 → 지문 확인 → 발급 항목 선택 → 부수 선택 → 결제 방법 → 모의 결제 → 인쇄 → 완료 → 처음 화면 복귀

기존 업무 흐름을 변경하지 마세요.

실제 개인정보가 아닌 테스트용 값만 사용합니다.
