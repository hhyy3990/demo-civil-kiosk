# 무인민원발급기 — 발급 불가 안내 모달 스크롤 점프 원인 분석 및 최소 수정

현재 무인민원발급기에는 공통 SDK `@naebangsik/kiosk-accessibility-sdk@0.4.1`이 설치돼 있습니다.

하단 조작 모드 60%·70%·80%, 자동 글씨 확대, 스크롤 안내, 숫자 키패드 및 전체 발급 과정은 대체로 정상 작동합니다.

그러나 **발급 불가 증명서 메뉴를 눌러 안내 모달을 열면 배경 화면이 위로 튀는 문제**가 남아 있습니다.

이전 Replit Preview 검증에서는 `.stage.scrollTop`이 640px에서 323px로 변경됐고, 모달을 닫은 뒤에도 323px에 머물렀습니다.

반면 QR 설정 모달에서는 같은 문제가 재현되지 않았습니다.

이번 작업은 두 모달을 비교하여 정확한 원인을 찾고, 필요하다면 최소한의 안전한 수정을 진행하는 것입니다.

## 1. 두 모달 구현 구조 비교

발급 불가 안내 모달과 QR 설정 모달의 다음 내용을 비교해 주세요.

- React 컴포넌트 구조
- 모달 DOM이 삽입되는 위치
- React Portal 사용 여부
- position: fixed / absolute
- z-index 및 containing block
- SDK overlay 등록 방식
- 모달 열기 전후 DOM 변화
- useEffect 및 useLayoutEffect
- 모달 열기·닫기 상태 관리
- 포커스 이동·복귀 코드
- body 또는 .stage 스크롤 잠금 여부

특히 발급 불가 안내 모달을 열 때 SDK가 `.stage`를 다시 측정하거나 위치를 변경하는지 확인해 주세요.

QR 설정 모달은 정상 작동하고 있으므로 두 모달의 차이를 중심으로 조사하되, 단순히 QR 모달 코드를 복사하는 방식으로 해결하지 마세요.

## 2. 스크롤 이동 시점 정밀 측정

390×844, 하단 조작 모드 80%, 아주 큰 글씨·큰 버튼·고대비 조건에서 우선 재현합니다.

다음 시점에 값을 기록해 주세요.

1. 발급 불가 메뉴를 누르기 직전
2. pointerdown 직후
3. click 이벤트 직후
4. React 모달 상태 변경 직후
5. 모달 DOM 삽입 직후
6. SDK overlay 갱신 직후
7. 다음 requestAnimationFrame
8. 100ms·500ms·1초 후
9. 모달 닫기 직후 및 1초 후

측정값:

- .stage.scrollTop
- .stage.scrollHeight / clientHeight
- 최대 스크롤 가능 거리
- document.scrollingElement.scrollTop
- .stage.getBoundingClientRect()
- 클릭한 메뉴 버튼의 getBoundingClientRect()
- document.activeElement
- 모달의 getBoundingClientRect()
- 관련 요소의 overflow 및 position
- SDK observer 실행 여부

**스크롤이 최초로 변경되는 정확한 시점**을 찾는 것이 중요합니다.

## 3. 원인 후보별 분리 실험

다음 요인을 가능한 한 하나씩 분리해 주세요.

A. 브라우저 scroll anchoring

B. 메뉴 버튼 클릭 및 포커스 이동

C. 모달을 DOM에 삽입하면서 발생하는 레이아웃 변화

D. SDK의 viewport overlay 등록 및 위치 재계산

E. SDK 자동 글씨 확대·레이아웃 보정 실행

F. 모달 열림에 따른 overflow 또는 스크롤 소유 요소 변화

G. React의 화면 전환 및 스크롤 초기화 로직

필요하다면 개발 전용 실험에서 scroll anchoring이나 포커스 처리를 일시적으로 비활성화하여 원인을 구분할 수 있습니다.

단, 해당 임시 실험을 그대로 최종 접근성 해결책으로 사용하지 마세요.

## 4. 원인이 확인된 경우 최소 수정

### 호스트 모달 문제라면

무인민원발급기에서 최소한으로 수정해 주세요.

- 모달 열림·닫힘 시 배경 스크롤 위치 유지
- 기존 발급 메뉴 위치 유지
- 모달 내부 조작 정상 동작
- 포커스 이동 및 키보드 접근성 유지
- 모달 닫기 후 기존 메뉴 버튼으로 적절하게 포커스 복귀
- Esc 및 닫기 버튼 정상 동작
- 배경 조작 방지와 모달 접근성 유지

단순히 모달이 열릴 때마다 scrollTop을 강제로 복원하는 반복 코드는 사용하지 마세요.

### 공통 SDK 문제라면

SDK 내부 코드를 직접 수정하지 마세요.

대신 다음을 구체적으로 보고해 주세요.

- 원인이 되는 SDK 함수
- 재현 가능한 최소 DOM 구조
- 스크롤 이동을 발생시키는 정확한 처리 단계
- SDK 수정으로 해결해야 하는 이유
- 카페·병원·은행에서도 발생할 수 있는 조건

해당 결과를 바탕으로 데모커피 프로젝트에서 SDK를 수정하겠습니다.

### 원인을 확정하지 못했다면

추측에 근거해 수정을 적용하지 말고, 재현 로그와 남은 가능성을 보고해 주세요.

## 5. 브라우저 회귀 검사

다음 화면을 검증합니다.

- 320×844
- 390×844
- 1080×1920

하단 조작:

- 60%
- 70%
- 80%
- 하단 조작 미사용

확인 사항:

- 발급 불가 모달 열림·닫힘 시 스크롤 위치 유지
- QR 설정 모달 정상 유지
- 모달 내부 스크롤과 배경 스크롤 분리
- 모달이 고정 하단 버튼과 겹치지 않음
- 스크롤 안내가 처음부터 나타나고 최하단에서 숨김
- 스마트 길잡이와 스크롤 안내 우선순위 유지
- 숫자 키패드 0~9 입력 가능
- 모달을 닫은 뒤 메뉴 선택 가능
- 화면 크기 변경 후 정상 동작

모든 조합에서 같은 현상이 나타나는지 구분하고, 핵심 재현 조건은 반드시 실제 브라우저 상호작용으로 검증해 주세요.

### 가장 중요한 합격 기준

**사용자가 아래쪽 증명서 메뉴를 누르고 안내 모달을 열었다 닫아도, 이전에 보고 있던 메뉴 위치가 의도치 않게 바뀌지 않아야 합니다.**

반드시 실제 브라우저의 scrollTop과 클릭 좌표로 검증하고, 원인이 확인되지 않으면 해결됐다고 보고하지 마세요.
