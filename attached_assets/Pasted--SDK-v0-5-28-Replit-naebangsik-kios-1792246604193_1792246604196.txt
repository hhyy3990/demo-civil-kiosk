# 무인민원발급기 — 최신 SDK v0.5.28 설치 및 스마트 길잡이 실제 검증

현재 프로젝트는 **무인민원발급기 Replit**입니다.

첨부한 `naebangsik-kiosk-accessibility-sdk-0.5.28.tgz`는 데모커피의 공통 SDK 원본에서 스마트 길잡이 자동 페이지 분할과 표시 시간 개선을 적용한 최신 검증용 패키지입니다.

이번 작업의 목표는 다음과 같습니다.

1. 최신 SDK v0.5.28 설치
2. 실제 무인민원발급기 스마트 길잡이의 문구 잘림 해결 여부 확인
3. 최대 2페이지 및 10·15·20초 표시 규칙 검증
4. 기존 접근성 오류 재발 방지
5. 검증 통과 시 중단됐던 전체 민원발급 절차 완료

**새로운 기능·디자인·안내 문구·업무 로직은 승인 없이 변경하지 마세요.**

- 패키지명: `@naebangsik/kiosk-accessibility-sdk`
- 버전: `0.5.28`
- 파일 크기: `89,161 bytes`

- 최신 패키지 설치
- package.json 및 package-lock.json 갱신

SDK 내부 소스, 무인민원발급기 CSS 및 업무 로직은 수정하지 않습니다.

## 2. 스마트 길잡이 실제 문구 조사

먼저 무인민원발급기의 기존 `setGuideState()`에 전달되는 실제 스마트 길잡이 문구를 확인하세요.

특히 이전에 본문이 약 20px 잘렸던 결제 단계의 문구를 확인합니다.

기존 측정값:

- 화면: 320×844
- 글씨 매우 크게
- 버튼 크게
- 고대비
- 쉬운 말 활성화
- 하단 80%
- 결제 단계 스마트 길잡이 약 67자
- 패널 높이 약 134.6px
- 기존 내부 콘텐츠 높이 약 154px
- 기존 본문 하단 약 20px 잘림

먼저 실제 문구의 stepId, 제목, 본문, 문자 수를 확인하세요.

**원문을 임의로 수정하거나 요약하지 마세요.**

## 3. 최대 2페이지 표시 검증 — 최우선

다음 화면 크기에서 실제 발급 절차를 통해 결제 화면까지 이동하세요.

- 320×844
- 360×667
- 390×844

테스트 설정:

- textSize: extraLarge
- buttonSize: large
- contrast: high
- easyLanguage: true
- smartGuide: true
- viewportMode: bottom 80%
- slowGuidance: false

확인할 항목:

1. 스마트 길잡이가 실제로 나타나는지
2. 전체 몇 페이지가 필요한지
3. 한 페이지라면 문구 전체가 표시되는지
4. 두 페이지라면 자동 전환되는지
5. 세 페이지 이상이 필요해 표시가 억제되는지
6. 제목·본문 잘림 여부
7. 원문 누락·중복 여부
8. 패널 상단 Y 좌표 안정성
9. 업무 화면 및 버튼 클릭 가능 여부
10. 브라우저 오류·무한 재귀 여부

각 화면 크기에서 실제 DOM의 패널 높이, 본문 높이, scrollHeight/clientHeight 및 잘림 픽셀 수를 측정하세요.

**3페이지 이상 필요하다는 이유로 스마트 길잡이가 표시되지 않는 경우에도 성공으로 보고하지 마세요.**

해당 stepId와 실제 문구, 필요한 페이지 수, 가용 높이를 보고하세요.

새로운 표시 방식이나 자동 요약은 추가하지 않습니다.

## 4. 표시 시간 검증

이번 SDK에 적용된 규칙은 다음과 같습니다.

- 기본 한 페이지: 총 10초
- 기본 두 페이지: 총 15초, 각 7.5초
- 느린 안내 한 페이지: 총 20초
- 느린 안내 두 페이지: 총 20초, 각 10초
- 스마트 길잡이 최대 2페이지

등장 전 대기 시간은 QR 설정의 `guideDelaySeconds`를 그대로 따릅니다.

다음 항목을 검증하세요.

- 등장 전 대기 시간과 등장 후 표시 시간 구분
- 첫 페이지 등장 시각
- 두 번째 페이지로 자동 전환하는 시각
- 최종 종료 시각
- 단계 변경 시 기존 안내 정리
- 같은 단계에서 입력·선택·스크롤할 때 타이머 재시작 없음

실제 결제 안내가 한 페이지라면 해당 실제 문구로 한 페이지 시간을 검증하고, 두 페이지 검증은 기존 테스트 fixture를 사용할 수 있습니다.

테스트를 위해 실제 발급 업무 안내 문구를 변경하지 마세요.

## 5. 쉬운 말 접힘 상태 복원

다음 절차를 확인하세요.

1. 쉬운 말 안내 펼침
2. 특정 페이지로 이동
3. 쉬운 말 접기
4. 스마트 길잡이 대기
5. 스마트 길잡이 등장 시 자동 펼침
6. 한 페이지 또는 두 페이지 표시
7. 표시 시간 종료
8. 기존 쉬운 말 안내로 복귀
9. 원래 페이지 및 접힘 상태 복원

패널 위치가 이동하거나 업무 화면이 자동 스크롤되면 안 됩니다.

## 6. 기존 쉬운 말 오류 재발 검증

다음 두 실제 업무 화면을 확인하세요.

- `certificate.type-selection`
- `certificate.id-input`

이전 검증 결과:

| 화면 | 320×844 | 360×667 | 390×844 |
|---|---|---|---|
| 등본 종류 안내 | 4페이지 | 6페이지 | 2페이지 |
| 주민등록번호 안내 | 5페이지 | 9페이지 | 4페이지 |

페이지 수는 실제 렌더링 결과에 따라 달라질 수 있으므로 무조건 같은 수를 강제하지 마세요.

필수 조건:

- 66·137페이지 오류 재발 없음
- 한 글자씩 비정상적인 분할 없음
- 원문 누락·중복 없음
- 본문·버튼 잘림 없음
- 페이지 전환 시 상단 Y 좌표 약 8px 유지
- 무한 재귀 없음

이전에 관찰된 페이지 번호의 비연속적 변화도 다시 기록하세요.

예: `1/4 → 3/7 → 4/7`

이 문제가 남아 있더라도 문구 누락과 별개로 구분해 보고하고, 승인 없이 페이지 표시 정책을 변경하지 마세요.

## 7. 첫 메뉴와 하단 80% 유지

기존에 적용한 첫 메뉴 안내를 변경하지 마세요.

제목: 쉬운 말 안내가 켜져 있어요.

본문: 업무를 선택하면 어려운 말을 쉽게 설명해 드려요.

검증 사항:

- 첫 메뉴 포함 자동 하단 80% 적용
- 쉬운 말 끔 + 하단 미설정 → 일반 화면
- 명시적 60·70·80% 선택 유지
- 실제 업무 단계에서는 단계별 안내 표시
- QR 원본 설정값 변경 없음

## 8. 기존 기능 전체 회귀

앞선 핵심 스마트 길잡이 오류가 해결된 경우 다음을 진행하세요.

- QR v1~v4 호환성
- 실제 Production QR 조회 경로
- QR 도크 정상 표시
- 카메라 QR 인식
- 큰 글씨·큰 버튼·고대비
- 스크롤 힌트 하단 12px 위치 유지
- 스크롤 도중 위아래 위치 점프 없음
- 스크롤 끝에서 힌트 숨김
- 주민등록등본 종류 선택
- 주민등록번호 키패드
- 지문 확인 시뮬레이션
- 증명서 표시 항목
- 수수료 면제 여부
- 발급 부수
- 신청 내용 확인
- 결제 시뮬레이션
- 인쇄 시뮬레이션
- 발급 완료
- 자동 복귀 및 접근성 설정 초기화

실제 개인정보를 입력하지 마세요.

기존 키오스크 업무 순서와 기능을 변경하지 마세요.

실제 카메라 하드웨어 테스트가 불가능하다면 미검증으로 보고하세요.

## 9. 오류 발견 시 대응

공통 SDK 오류라면 무인민원발급기 호스트에서 우회 수정하지 마세요.

다음 내용을 기록하고 해당 검증을 중단하세요.

- 화면 크기
- 적용 프로필
- stepId
- 실제 안내 원문
- 패널 높이
- 본문 높이
- 필요 페이지 수
- 잘림 픽셀
- 타이머 상태
- 관련 콘솔 오류

호스트 CSS 수정, 안내 문구 자동 축약, SDK 내부 수정, 신규 기능 추가는 금지합니다.

특히 기존에 해결한 페이지 분할·무한 재귀·상단 패널 위치·하단 스크롤 안내 문제가 재발하지 않아야 합니다.
