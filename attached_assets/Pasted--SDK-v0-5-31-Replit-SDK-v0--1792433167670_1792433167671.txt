# 무인민원발급기 — SDK v0.5.31 설치 및 스크롤 안내 충돌 최종 검증

현재 프로젝트는 **무인민원발급기 Replit**입니다.

이번 작업의 목표는 공통 SDK v0.5.31을 설치하고, v0.5.30에서 발견된 **쉬운 말 안내가 스크롤 안내 OFF 설정을 강제로 ON으로 바꾸는 오류**가 실제 무인민원발급기에서 해결됐는지 검증하는 것입니다.

이미 이전 버전에서 검증한 모든 업무 기능을 처음부터 장시간 재검사하지 마세요.

**이번 작업은 SDK 설치와 최소 회귀 검증만 승인합니다. 호스트 소스·CSS 및 SDK 내부 코드는 수정하지 마세요.**

## 1. SDK 패키지 확인 및 설치

업로드된 tarball을 확인하세요.

- 패키지: `@naebangsik/kiosk-accessibility-sdk`
- 버전: `0.5.31`
- 파일명: `naebangsik-kiosk-accessibility-sdk-0.5.31.tgz`
- 크기: `90,444 bytes`
- SHA-256: `c75ea538fed1b59dbb89bcf5cd22f8e7f5b66c50312581cf592ec4b4f714bc94`

크기, 해시, 패키지 내부 버전이 모두 일치할 때만 설치하세요.

일치하면 다음을 진행하세요.

1. 기존 v0.5.30 tarball 보존
2. 최신 v0.5.31 설치
3. package.json·package-lock.json 갱신
4. 필요한 경우 이전 Vite 캐시 정리
5. Preview 재시작
6. 실제 로드된 SDK JS/CSS와 설치 tarball 내용 일치 확인
7. 타입 검사 및 프로덕션 빌드

동일 버전의 파일을 반복 덮어쓰지 말고, 실제 버전 0.5.31이 적용됐는지 확인하세요.

## 2. 최우선 — 쉬운 말과 스크롤 안내 ON/OFF 충돌 검증

v0.5.30에서 발견된 오류는 다음과 같습니다.

- QR 프로필에서 `scrollGuidance:false` 적용
- 이후 쉬운 말 안내가 표시됨
- SDK의 안내 렌더링 경로가 스크롤 안내를 다시 ON으로 변경
- 결과적으로 사용자가 꺼둔 스크롤 안내가 표시됨

v0.5.31은 모든 관련 경로가 현재 QR 프로필의 `scrollGuidance`를 따르도록 수정됐습니다.

### 실제 검증 조건

브라우저 내 합성 QR 응답을 사용하세요.

중앙 QR 서비스나 Production DB에 요청하거나 프로필을 새로 생성하지 마세요.

390×844 화면에서 다음을 확인하세요.

| 프로필 조건 | 기대 결과 |
|---|---|
| QR 미적용 | 안내 OFF |
| v1~v4, 쉬운 말 ON | 안내 OFF |
| v5 `scrollGuidance` 누락, 쉬운 말 ON | 안내 OFF |
| v5 `scrollGuidance:false`, 쉬운 말 ON | 안내 OFF |
| v5 `scrollGuidance:true`, 쉬운 말 ON | 안내 ON |

스크롤할 내용이 실제로 있는 화면에서 확인하세요.

**안내 OFF는 스크롤 위치 때문에 잠시 숨겨진 상태와 구분해야 합니다.**

필요하다면 안내 DOM 생성·제거 및 현재 활성화 상태도 함께 확인하세요.

## 3. 기존 오류 재발 방지

스크롤 안내 OFF 상태에서 다음 동작을 순서대로 수행하세요.

1. 쉬운 말 안내 활성화
2. 쉬운 말 1페이지 → 2페이지 이동
3. 이전 페이지로 이동
4. 다른 업무 단계로 이동
5. 스마트 길잡이 등장
6. 스마트 길잡이 X 클릭
7. 기존 쉬운 말 페이지 복귀
8. 동일 단계에서 안내 상태 갱신

위 과정 전체에서 **스크롤 안내 OFF가 유지돼야 합니다.**

특히 Easy Language 페이지 이동이나 Smart Guide 종료가 스크롤 안내를 다시 켜면 실패입니다.

스마트 길잡이는 X 클릭 이후 같은 단계에서 30초 이상 재등장하지 않는지 한 번 확인하세요. 다음 단계에서는 정상 동작해야 합니다.

## 4. ON 상태와 고정 버튼 겹침

v5 `scrollGuidance:true`를 적용하세요.

다음만 확인하세요.

- 스크롤할 내용이 있으면 안내 표시
- 끝까지 스크롤하면 숨김
- 다시 위로 스크롤하면 표시
- 고정 파란 QR 도크 버튼과 교차 면적 0
- 하단 `처음화면`·`전화면` footer와 교차 면적 0
- pointer-events:none 유지
- 실제 업무 스크롤 정상

390×844 기본 모드를 우선 검사하고, 360×667 자동 하단 80%를 대표 조건으로 한 번 더 확인하세요.

**일반 콘텐츠와 스크롤 안내가 겹치는 것은 정상입니다.**

증명서 카드·입력창·키패드 등 스크롤되는 일반 콘텐츠와의 겹침을 오류로 보고하지 마세요.

기존 고정 조작부 회피 계산을 변경하지 마세요.

## 5. 프로필 전환과 초기화

가능한 기존 방식으로 다음 순서를 확인하세요.

`QR 없음 OFF → v5 true ON → v5 false OFF → v5 true ON → v4 OFF → 세션 초기화 OFF`

- OFF 시 안내가 제거됨
- ON 시 중복 안내 없이 재표시
- v4 적용 시 OFF로 돌아감
- 처음 화면 복귀 및 세션 초기화 후 OFF 유지
- 이전 프로필의 ON 상태가 남지 않음
- 메뉴 18개 유지

호스트의 실제 UI가 동일 세션 내 프로필 재적용을 지원하지 않는다면, 검증용 기존 API·테스트 환경에서만 확인하고 해당 사실을 명시하세요.

새로운 호스트 기능을 구현하지 마세요.

## 6. 쉬운 말 안내의 원문 보존

v0.5.30의 실제 Preview에서 주민등록번호 안내가 390×844 기준 4페이지로 나뉘었습니다.

이것만으로는 오류가 아닙니다.

다음만 확인하세요.

- 기존 안내 문구 전체 보존
- 페이지별 누락·중복 없음
- 이전·다음 버튼 정상
- 페이지 수 안정적
- 한 글자 또는 한 단어씩 나뉘는 비정상적인 과분할 없음

**4페이지를 무조건 줄이거나 글자 크기를 축소하지 마세요.**

자동 하단 80% 및 명시적 하단 70% 기능도 유지해야 합니다.

## 7. 전체 발급 흐름 최소 회귀

앞선 핵심 검증이 통과하면 다음을 한 번만 확인하세요.

- 주민등록표 등본 선택
- 임의 테스트 숫자 13자리 입력
- 지문 확인 시뮬레이션
- 발급 옵션 및 부수 선택
- 가상 결제
- 인쇄·완료
- 약 15초 후 처음 화면 복귀
- 입력값·접근성 설정 초기화
- 새 세션에서 스크롤 안내 OFF

실제 개인정보나 실제 결제 정보를 사용하지 마세요.

기존 QR v1~v5의 모든 접근성 설정을 전수검사할 필요는 없습니다.

## 8. 실패 시 처리

다음 중 하나라도 발견되면 해당 상황을 측정·보고하고 코드 수정은 중단하세요.

- v5 false 또는 필드 누락에서 안내 ON
- v1~v4에서 쉬운 말이 스크롤 안내를 켬
- 업무 단계 변경 후 OFF가 ON으로 바뀜
- 고정 QR 도크·footer 겹침 재발
- 쉬운 말 본문 손실
- 스마트 길잡이 X 후 같은 단계 재등장
- 기존 발급 과정 실패

실패 보고에는 화면 크기, QR 프로필, stepId, 재현 단계, DOM 상태, 관련 SDK 경고를 포함하세요.

**무인민원발급기 호스트 CSS 또는 SDK 내부를 임의 수정하지 마세요.**
