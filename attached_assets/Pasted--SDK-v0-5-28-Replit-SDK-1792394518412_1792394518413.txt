# 무인민원발급기 — 최신 SDK v0.5.28 설치 및 실제 화면 회귀 검증

현재 프로젝트는 **무인민원발급기 Replit**입니다.

이번 작업의 목표는 데모커피 공통 SDK에서 수정한 다음 기능을 실제 무인민원발급기 화면에서 검증하는 것입니다.

1. 쉬운 말 안내의 과도한 페이지 분할 개선
2. 하단 70% 모드의 이전·다음 버튼 배치 개선
3. 기본 모드의 스크롤 안내와 하단 고정 버튼 겹침 해결
4. 기존 스마트 길잡이와 전체 발급 흐름 유지 확인

**새로운 기능이나 디자인 변경은 하지 마세요. 기존 호스트의 업무 로직·CSS·안내 문구도 수정하지 마세요.**

## 1. 최신 SDK 설치

첨부 tarball의 정보를 먼저 확인하세요.

- 패키지: `@naebangsik/kiosk-accessibility-sdk`
- 버전: `0.5.28`
- 크기: `90,395 bytes`
- SHA-256: `facb0e86873eb34f3b08f0c9e5c74e9b7fca210ea1b0219d3eed7ac6764fad36`

파일 크기나 해시가 다르면 설치하지 말고 보고하세요.

일치하면 다음을 진행하세요.

- 기존 SDK tarball 보존
- 최신 SDK 설치
- package.json 및 package-lock.json 갱신
- Vite Preview 재시작
- 실제 브라우저에 최신 JS/CSS가 적용됐는지 파일 해시로 확인
- 타입 검사 및 빌드

같은 버전 번호라도 이전 tarball과 내용이 다르므로 캐시된 이전 빌드를 사용하지 않도록 주의하세요.

## 2. 최우선 검증 — 쉬운 말 안내 과분할

사용자가 실제 화면에서 발견했던 오류입니다.

- 주민등록표 종류 선택 화면
- stepId: `certificate.type-selection`
- 과거 현상: `1/21`까지 과도하게 분할
- 첫 페이지에 `주민등록표` 한 단어만 표시되던 문제

현재 호스트의 실제 안내 원문을 그대로 사용하세요.

항목 1:

제목: 주민등록표 등본

본문: 주민등록표 등본은 한 세대의 구성과 주소 정보를 확인하는 주민등록 서류입니다.

항목 2:

제목: 주민등록표 초본

본문: 초본 발급은 아직 준비 중입니다. 이 데모에서는 등본만 진행할 수 있습니다.

다음 화면 크기에서 검증하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

설정:

- textSize: extraLarge
- buttonSize: large
- contrast: high
- easyLanguage: true
- smartGuide: true
- viewportMode: null → 자동 하단 80%

공통 SDK의 독립 fixture에서는 최근 다음 결과가 나왔습니다.

- 320×844: 4페이지
- 360×667: 4페이지
- 390×844: 2페이지
- 1080×1920: 2페이지

실제 무인민원발급기에서 결과가 같은지 확인하세요.

**페이지 수가 다르더라도 바로 실패로 단정하지 말고, 원문 보존·실제 본문 가용 높이·과분할 여부를 확인하세요.**

특히 다음이 중요합니다.

- 한 글자 또는 한 단어만 반복해서 표시되지 않음
- 원문 누락·중복 없음
- 한 페이지에 읽을 만한 문장량 표시
- 본문·제목·버튼 잘림 없음
- 이전·다음 버튼 정상
- 페이지 이동 중 총 페이지 수가 비정상적으로 바뀌지 않음
- 패널 상단 위치 안정성
- 무한 재귀 오류 없음

실제 각 페이지에 표시된 문구와 페이지 수를 기록하세요.

## 3. 하단 70% 쉬운 말 안내

이번 SDK에서는 하단 70%에서 이전·다음 버튼이 별도 줄을 차지하지 않도록 좁은 패널 배치를 개선했습니다.

360×667에서 확인하세요.

설정:
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 활성화
- viewportMode: bottom 70%

SDK 독립 fixture의 결과:

- 수정 전: 6페이지
- 수정 후: 2페이지
- 본문 영역: 약 72px
- 헤더: 44px

실제 무인민원발급기에서도 다음을 확인하세요.

1. 이전·다음 버튼과 접기 버튼이 상단 영역에 배치되는지
2. 별도 페이지 조작부 줄이 불필요하게 생기지 않는지
3. 2페이지 안팎으로 읽기 좋게 분할되는지
4. 제목·버튼이 겹치지 않는지
5. 터치 영역 44×44px 유지 여부
6. 원문·잘림·페이지 번호 안정성
7. 하단 70% 업무 영역 유지

명시적 하단 60%와 80%도 간단히 비교하되, 정상인 배치를 추가 수정하지 마세요.

## 4. 기본 모드 스크롤 안내 위치

사용자가 실제 화면에서 발견한 문제입니다.

기존 기본 모드 390×844:

- 스크롤 안내: y=787.61~832
- 하단 footer: y=758~844
- `처음화면`·`전화면` 버튼과 실제 겹침

최신 SDK는 호스트가 이미 등록한 `bottomControls`를 활용하도록 수정됐습니다.

390×844 기본 화면에서 확인하세요.

- 실제 스크롤 owner: Document
- 스크롤 안내가 footer 위에 표시되는지
- footer 상단과 약 12px 간격을 유지하는지
- `처음화면`·`전화면` 버튼과 겹치지 않는지
- 스크롤 중 안내 위치가 튀지 않는지
- 스크롤 끝에서 숨겨지는지
- pointer-events:none 유지

기존 DOM 구조:

- scrollArea: `main.stage`
- bottomControls: `.device-footer`
- footer는 모바일에서 fixed

다음 모드에서도 정상 위치가 유지되는지 확인하세요.

- 일반 모드
- 하단 70%
- 하단 80%

공통 SDK 독립 fixture에서는 기본 모드 footer 위 12px, 하단 모드 약 12~13px가 확인됐습니다.

**이번에는 실제 무인민원발급기 DOM에서 스크롤 안내와 footer의 좌표를 측정하세요.**

호스트 CSS에 새로운 위치 값을 하드코딩하지 마세요.

## 5. 스마트 길잡이 회귀

이번 SDK는 이전에 정상 작동했던 스마트 길잡이의 줄 높이 `1.25`를 복원했습니다.

실제 결제 화면에서 검증하세요.

stepId: `certificate.payment-method`

기존 문구:

증명서 종류, 발급 부수, 표시 항목과 수수료를 확인해 주세요. 내용이 맞으면 결제 방법을 눌러 가상 결제를 진행하세요.

화면:
- 360×667
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 하단 80%
- Smart Guide 활성화

성공 기준:

- 67자 원문 보존
- 최대 2페이지로 표시
- 본문 잘림 없음
- 약 7.5초 후 두 번째 페이지
- 총 약 15초 표시
- 느린 안내는 총 약 20초, 페이지당 약 10초
- 짧은 한 페이지 안내는 기본 10초
- 등장 전 guideDelaySeconds 유지
- 쉬운 말 접힘·페이지 상태 복원
- 상단 패널 약 8px 유지

실제 표시 시각과 전환 시각을 구분해 측정하세요.

이번에 검증할 것은 기존 동작의 유지 여부이며, 스마트 길잡이의 정책을 변경해서는 안 됩니다.

## 6. 전체 발급 흐름 핵심 회귀

앞의 세 가지 핵심 화면 문제가 해결된 경우에만 다음 흐름을 확인하세요.

- 주민등록표 등본 선택
- 임의 테스트 숫자 13자리 입력
- 지문 확인 시뮬레이션
- 표시 항목 및 발급 부수 선택
- 수수료 확인
- 가상 결제
- 인쇄
- 발급 완료
- 15초 후 첫 화면 복귀
- 접근성 설정과 입력값 초기화
- 메뉴 18개 유지

실제 개인정보를 입력하지 마세요.

기존에 검증했던 업무 흐름을 변경하거나 새로운 단계·버튼을 추가하지 마세요.

## 7. QR 호환성

현재 호스트와 SDK의 기존 QR 기능이 유지되는지 확인하세요.

- QR v1~v4 합성 응답 호환성
- QR 프로필 적용 및 설정 복원
- 자동 하단 80% 적용
- 명시적 하단 60·70·80%
- 기존 QR 도크와 메뉴 동작

안전한 기존 Production 테스트 QR이 있다면 읽기 전용 조회만 확인할 수 있습니다.

없다면 Production DB에 테스트 프로필을 새로 만들지 말고 실제 Production 조회는 미검증으로 보고하세요.

실제 카메라 장치가 없는 브라우저에서는 카메라 인식도 미검증으로 보고하세요.

이전 테스트의 합성 QR 통과 결과를 실제 Production QR 검증으로 표현하지 마세요.

## 8. 오류 발견 시

공통 SDK 문제로 판단되면 무인민원발급기 호스트에서 우회 수정하지 마세요.

다음 항목을 기록하세요.

- 화면 크기와 프로필 설정
- stepId
- 패널·본문·헤더 높이
- 페이지 수 및 페이지별 원문
- footer와 스크롤 안내 좌표
- 실제 겹침·잘림 여부
- 관련 SDK 경고와 브라우저 오류

핵심 오류가 발견되면 해당 검증을 중단하고 보고하세요.

새 기능 추가, 자동 문구 축약, 호스트 CSS 수정, SDK 소스 직접 변경은 금지합니다.
