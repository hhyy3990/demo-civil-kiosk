# 무인민원발급기 — 최신 SDK 설치 및 두 가지 오류 최종 검증

현재 프로젝트는 **무인민원발급기 Replit**입니다.

데모커피 공통 SDK에서 다음 두 가지 오류를 수정한 최신 패키지가 만들어졌습니다.

1. 스크롤 안내가 고정된 파란색 `내 QR로 화면 설정` 버튼의 글씨를 가리는 오류
2. 쉬운 말·스마트 길잡이 접기/펼치기 제거 및 스마트 길잡이 X 종료 시 쉬운 말 복귀

이번 작업은 **최신 SDK 설치와 실제 무인민원발급기 화면 검증**입니다.

호스트 업무 로직·CSS·안내 문구는 수정하지 마세요. 문제가 발견되면 측정 결과만 보고하고 추가 수정은 사용자 승인을 기다리세요.

## 1. SDK 설치

업로드한 tarball을 확인하세요.

패키지: `@naebangsik/kiosk-accessibility-sdk`

버전: `0.5.28`

파일 크기: `89,507 bytes`

SHA-256:
`2acac28a4ec535566affb31d83617fc49e5d043b2fae0564c8ed28a7c0e5aa02`

크기와 해시가 모두 일치하는 경우에만 설치하세요.

- 기존 tarball 백업·보존
- 최신 SDK 설치
- package.json 및 package-lock.json 갱신
- 오래된 Vite prebundle 캐시 정리
- Preview 재시작
- 실제 브라우저에서 최신 SDK JS/CSS 사용 여부 확인
- 타입 검사·빌드

같은 버전 v0.5.28의 이전 패키지가 여러 개 존재하므로, 파일명이나 npm 버전만으로 설치 성공이라고 판단하지 마세요.

**실제 설치 파일과 업로드된 tarball의 JS/CSS 해시를 비교하세요.**

## 2. 최우선 — 파란 QR 버튼과 스크롤 안내

사용자가 실제 화면에서 발견한 오류입니다.

문제 발생 화면:

- 무인민원발급기 첫 메뉴
- 기본 모드
- 390×844

고정 파란 버튼:

`ASIDE.a11y-qr-entry-dock[data-a11y-qr-entry-dock="true"]`

내부 버튼:

`BUTTON.a11y-qr-entry-dock-button`

버튼 문구:

`내 QR로 화면 설정`

기존 측정:

- QR dock: Y=686~758
- QR 버튼: Y=696.5~748.5
- 스크롤 안내: Y=701.61~746
- 버튼과 안내의 교차 면적: 약 9,667px²

이전 SDK에서는 스크롤 안내가 `.device-footer`만 회피하고 QR dock을 회피하지 않았습니다.

새 SDK는 `bottomControls`, `guidanceAvoidAreas`, SDK 생성 QR dock을 고려하고 실제 고정 영역과 겹칠 때만 위치를 조정하도록 수정됐습니다.

### 성공 기준

실제 호스트 DOM에서 다음을 측정하세요.

1. QR dock 위치
2. QR 버튼 위치
3. 스크롤 안내 위치
4. `.device-footer` 위치
5. 스크롤 안내와 QR 버튼의 교차 면적
6. 스크롤 안내와 footer의 교차 면적

**두 고정 조작부와의 교차 면적이 모두 0이어야 합니다.**

가능하면 QR dock 상단과 스크롤 안내 하단 사이 간격도 보고하세요.

또한 다음을 확인하세요.

- 파란 버튼의 문구가 가려지지 않음
- QR 버튼 클릭 시 기존 QR 설정창 정상 표시
- 스크롤 중 고정 조작부와 겹치지 않음
- 맨 아래까지 스크롤하면 안내 숨김
- 스크롤 안내의 pointer-events:none 유지
- 스크롤 중 부자연스러운 위치 점프 없음

### 반드시 지킬 구분

**일반 스크롤 콘텐츠와 스크롤 안내가 겹치는 것은 정상입니다.**

증명서 선택 카드, 입력창, 키패드, 일반 메뉴 버튼 등 스크롤되는 콘텐츠 위에 안내가 겹치는 것은 오류로 판단하지 마세요.

일반 콘텐츠와의 겹침을 없애는 수정이나 추가 여백 확보는 금지합니다.

문제는 오직 **화면에 고정된 QR dock 또는 footer의 버튼을 스크롤 안내가 가리는 경우**입니다.

## 3. 쉬운 말 — 접기/펼치기 제거 확인

기존 쉬운 말 기능을 켜고 확인하세요.

- 접기/펼치기 버튼 없음
- 쉬운 말은 표시되는 동안 펼쳐진 상태 유지
- 이전·다음 페이지 버튼 정상
- 페이지 번호 정상
- 원문 누락·중복 없음
- 안내 제목·본문 잘림 없음

특히 다음 과거 오류가 재발하지 않았는지 확인하세요.

- `1/21`처럼 비정상적으로 페이지가 많아짐
- 한 글자 또는 한 단어만 표시
- 페이지 이동 중 총 페이지 수가 갑자기 변함
- 좁은 화면에서 버튼 겹침
- 안내 패널의 위치 점프

360×667에서 자동 하단 80%와 명시적 하단 70%를 우선 확인하세요.

이전 SDK에서는 주민등록표 종류 선택 안내가 자동 80%에서 4페이지, 명시적 70%에서 2페이지였습니다.

접기 버튼 제거로 본문 배치가 달라질 수 있으므로 **반드시 실제 페이지 수와 원문 보존 여부를 측정**하세요. 기존 페이지 수와 다르다는 사실만으로 실패 처리하지 말고 과분할·잘림 여부를 기준으로 판단하세요.

## 4. 스마트 길잡이 — X 버튼과 쉬운 말 복귀

스마트 길잡이를 활성화하고 실제 무인민원발급기 업무 단계에서 검증하세요.

### 버튼

- 접기/펼치기 버튼 없음
- X 버튼 유지
- 스마트 길잡이 본문은 항상 펼쳐진 상태
- 2페이지인 경우 기존 페이지 표시·전환 정상

### X 클릭 시나리오

1. 쉬운 말 안내가 표시된 상태에서 시작
2. 쉬운 말의 첫 페이지가 아닌 페이지로 이동
3. 스마트 길잡이가 등장할 때까지 기다림
4. 스마트 길잡이가 쉬운 말 안내를 대신해 표시되는지 확인
5. 스마트 길잡이 X 버튼 클릭
6. 스마트 길잡이가 즉시 사라지는지 확인
7. **직전에 보던 쉬운 말 페이지가 다시 표시되는지 확인**
8. 같은 업무 단계에서 스마트 길잡이가 불필요하게 재등장하지 않는지 확인

### 자동 종료

스마트 길잡이가 X 클릭 없이 자동 종료되는 경우에도 쉬운 말 안내로 돌아오는지 확인하세요.

기존 스마트 길잡이 시간 정책은 변경하지 마세요.

- 한 페이지 일반 안내: 총 10초
- 두 페이지 일반 안내: 총 15초, 약 7.5초 후 전환
- 느린 안내: 총 20초, 두 페이지면 약 10초 후 전환
- 등장 전 지연: guideDelaySeconds 10·15·20초
- 최대 2페이지
- 원문 생략 없음

360×667에서 결제 단계 `certificate.payment-method`의 기존 67자 안내가 2페이지로 정상 표시되는지 우선 확인하세요.

과거에 발생했던 Smart Guide의 4페이지 계산 후 미표시 오류와 본문 잘림도 재발하지 않아야 합니다.

## 5. 핵심 회귀 검사

앞의 두 오류가 해결된 경우에만 기존 기능을 간단히 확인하세요.

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

접근성 모드:

- 기본 모드
- 자동 하단 80%
- 명시적 하단 60·70·80%

핵심 검사:

- QR dock과 footer를 가리지 않는 스크롤 안내
- 일반 콘텐츠 겹침은 허용
- 쉬운 말 원문 보존 및 페이지 조작
- Smart Guide 최대 2페이지 및 시간 정책
- QR v1~v4 합성 응답 적용
- 메뉴 18개 유지
- QR 도크 클릭 및 QR 설정창 표시
- 등본 선택부터 가상 결제·인쇄·완료까지 진행
- 약 15초 후 첫 화면 복귀
- 입력값 및 접근성 설정 초기화
- 세션 종료 후 Smart Guide 재등장 없음

실제 주민등록번호나 민감정보를 입력하지 마세요. 테스트에는 임의 숫자만 사용하세요.

실제 Production QR 조회나 카메라·음성 재생이 불가능한 환경에서는 해당 항목을 미검증으로 보고하세요.

Production DB에 새 테스트 프로필을 생성하지 마세요.

**최종 성공 기준**

첫째, 스크롤 안내가 고정된 파란 `내 QR로 화면 설정` 버튼 및 하단 footer를 가리지 않아야 합니다. 일반 콘텐츠와 겹치는 것은 정상으로 유지합니다.

둘째, 쉬운 말과 스마트 길잡이에 접기/펼치기 버튼이 없어야 하며, 스마트 길잡이 X를 누르면 이전에 보던 쉬운 말 안내가 정상적으로 돌아와야 합니다.

이미 해결한 쉬운 말 과분할·스마트 길잡이 잘림·타이머 오류·스크롤 위치 점프가 재발해서는 안 됩니다.

두 조건 중 하나라도 실패하면 성공으로 보고하지 말고 실제 원인을 측정해 보고하세요.
