# 무인민원발급기 — 첫 화면 상단 잘림 및 화면 전환 시 스크롤 위치 초기화 수정

현재 무인민원발급기 프로젝트에는 공통 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.3`이 설치돼 있습니다.

QR 프로필 v3의 하단 조작 60·70·80% 자동 적용과 발급 시뮬레이션까지 검증했습니다.

그러나 실제 Preview를 새 브라우저 창으로 열어 확인한 결과, 사용자 경험에 직접적인 영향을 주는 두 가지 문제가 발견됐습니다.

**문제 1. 새 창에서 첫 화면을 열었을 때 상단이 잘린 상태로 표시됩니다.**

첨부 스크린샷처럼 증명서 메뉴 중간 부분부터 나타나고 상단 제목·설명 영역이 보이지 않습니다. 위로 스크롤해도 더 올라가지 않는 상황입니다.

**문제 2. 다음 화면으로 넘어갈 때 이전 화면의 스크롤 위치가 유지됩니다.**

예를 들어 증명서 목록을 아래로 스크롤한 상태에서 버튼을 눌러 다음 발급 화면으로 넘어가면, 새 화면이 맨 위가 아니라 이전 화면과 비슷한 스크롤 위치에서 시작합니다.

이번 작업에서는 이 두 가지 문제를 최우선으로 수정해 주세요.

## 1. 작업 범위

이번 수정의 핵심 원칙은 다음과 같습니다.

**키오스크를 새로 열었을 때 첫 화면의 첫 내용이 보이고, 다른 업무 화면으로 전환할 때마다 새로운 화면의 첫 내용부터 보여야 합니다.**

단, 사용자가 현재 화면 안에서 스크롤하는 것은 방해하면 안 됩니다.

다음 기능은 유지합니다.

- SDK v0.5.3
- QR 프로필 v1/v2/v3
- 하단 조작 60·70·80%
- 글씨·버튼 확대와 고대비
- QR 도크와 하단 고정 조작부
- 스크롤 안내
- 스마트 길잡이 및 음성 안내
- 기존 증명서 18개 메뉴
- 주민등록등본 발급 전체 과정

이번에는 이전에 발견한 최하단 메뉴 경계 사례와 키보드 포커스 가림 문제를 별도로 수정하지 않습니다. 해당 사항은 후속 개선 항목으로만 남겨 주세요.

## 2. 첫 화면 상단 잘림 원인 조사

먼저 첨부 스크린샷의 상태를 재현하고 DOM 및 스크롤 값을 측정해 주세요.

조사 대상:

- html
- body
- document.scrollingElement
- #root
- 키오스크 최상위 컨테이너
- `.stage`
- SDK가 적용한 하단 viewport 영역
- QR 도크
- 기존 하단 고정 조작부

확인 사항:

- 새 브라우저 창에서 초기 scrollTop
- 각 요소의 scrollHeight / clientHeight
- 각 요소의 실제 최대 스크롤 거리
- 첫 번째 제목 요소의 boundingClientRect
- 첫 번째 메뉴의 boundingClientRect
- overflow / transform / height / min-height
- SDK 초기화 전후 스크롤 위치
- React 최초 렌더링 및 레이아웃 적용 순서
- 브라우저의 스크롤 위치 복원 여부
- 화면 높이 변경이나 QR 도크 생성으로 기존 스크롤 위치가 보정되는지

특히 **실제 scrollTop이 0인데 상단 콘텐츠가 잘려 있다면, 단순 스크롤 초기화가 아니라 레이아웃 좌표·클리핑·transform 문제일 수 있습니다.**

이 경우 scrollTo(0, 0)만 추가해서 해결했다고 판단하지 마세요.

## 3. 첫 화면 최초 진입 동작

새 창에서 앱을 열거나 새로고침하면 반드시 첫 화면의 시작 내용이 보여야 합니다.

목표:

- 제목과 첫 번째 안내 영역 표시
- 증명서 메뉴 목록의 시작 부분 표시
- 초기 스크롤 위치 0
- QR 도크 정상 표시
- 기존 하단 버튼 정상 표시
- 위쪽 내용이 화면 밖으로 잘리지 않음
- 새로고침·창 크기 변경 후에도 첫 화면 접근 가능

브라우저가 이전 scrollY를 복원하거나, React·SDK 초기화로 콘텐츠 영역이 변하는 상황도 고려해 주세요.

필요한 경우 최초 화면 진입 시 스크롤 초기화를 수행하되, 레이아웃 적용 시점까지 검증해 실제로 정상 위치에 머무는지 확인해 주세요.

스크롤이 반복해서 맨 위로 튀는 무한 보정 구조는 금지합니다.

## 4. 화면 전환 시 스크롤 초기화 정책

**업무 단계가 실제로 변경되면 새로운 화면의 스크롤 위치를 맨 위로 초기화합니다.**

예시:

- 증명서 메뉴 → 주민등록등본 발급 화면
- 발급 화면 → 주민등록번호 입력
- 입력 화면 → 지문 확인
- 지문 확인 → 발급 옵션
- 발급 옵션 → 수수료 및 부수 선택
- 신청 내용 확인 → 결제
- 결제 → 인쇄·완료
- 각 단계에서 다음 단계로 이동
- 전화면 버튼을 눌러 이전 업무 단계로 돌아갈 때
- 처음화면 버튼으로 증명서 메뉴에 복귀할 때

화면 전환 시 반드시 새 화면의 제목·설명·첫 입력 항목이 처음부터 보이도록 합니다.

**스크롤 초기화는 버튼 클릭 자체가 아니라 실제 업무 화면 식별자의 변경을 기준으로 실행해 주세요.**

현재 화면에서 일반 메뉴를 펼치거나 입력값을 수정하는 동작 때문에 맨 위로 이동하면 안 됩니다.

또 같은 화면에서 React가 재렌더링되는 경우에도 사용자가 내린 스크롤을 유지해야 합니다.

## 5. 여러 스크롤 소유자 대응

기존 테스트에서 무인민원발급기의 화면에 따라 실제 스크롤 소유자가 달랐습니다.

- 증명서 메뉴에서는 `.stage`가 스크롤
- 긴 입력 화면에서는 document가 스크롤하는 사례가 있음

따라서 `.stage.scrollTop = 0`만 실행하는 단순 수정으로 끝내지 마세요.

실제 화면에 존재하는 스크롤 소유자를 확인하고, 업무 단계가 변경되면 이전 스크롤 위치가 다음 화면에 남지 않도록 처리해 주세요.

다음 사항을 확인합니다.

- document와 내부 컨테이너 중 실제 스크롤 소유자
- 이전 화면에서 사용하던 컨테이너의 재사용 여부
- 중첩 스크롤이 있는 경우 정확한 초기화 대상
- SDK의 방법 B가 활성화된 경우 스크롤 컨테이너의 변동
- 화면 전환 직후 React 렌더와 SDK 레이아웃 조정 간 순서
- 스크롤 복원 또는 autofocus가 초기화를 다시 뒤집는지 여부

필요한 경우 화면이 실제 DOM에 반영된 뒤 한 번 초기화하도록 구현하되, 임의의 setTimeout 반복 호출에 의존하지 마세요.

## 6. 초기화하면 안 되는 경우

다음 상황에서는 스크롤을 무조건 맨 위로 돌리면 안 됩니다.

- 현재 화면 안에서 사용자가 직접 스크롤
- QR 모달 열기·닫기
- 발급 불가 안내 모달 열기·닫기
- 스마트 길잡이 표시·닫기
- 스크롤 안내 표시·숨김
- 화면 크기 변경만 발생한 경우
- 입력값 변경
- 같은 화면에서 접근성 스타일이 다시 계산되는 경우

특히 이전에 해결한 **모달 열기·닫기 전후 스크롤 위치 0px 변화**라는 회귀 기준을 유지해 주세요.

QR 프로필 적용으로 글씨와 viewport 크기가 달라질 때에는 사용자가 현재 작업 중인 내용을 가능한 범위에서 유지하되, 잘린 상단에 갇히는 상황이 생기지 않도록 확인합니다.

## 7. QR 하단 조작 모드 검증

다음 모드를 각각 검증합니다.

- 일반 화면
- 하단 60%
- 하단 70%
- 하단 80%
- 아주 큰 글씨 + 큰 버튼 + 고대비 + 하단 60%
- 아주 큰 글씨 + 큰 버튼 + 고대비 + 하단 70%
- 아주 큰 글씨 + 큰 버튼 + 고대비 + 하단 80%

주의할 점은 방법 B에서는 화면 위쪽을 의도적으로 비워 두기 때문에 콘텐츠 영역 자체가 아래에서 시작할 수 있다는 것입니다.

이것은 정상입니다.

그러나 콘텐츠 영역 안에서는 새로운 화면의 첫 번째 제목과 안내가 잘리지 않은 상태로 보여야 합니다.

QR 도크와 기존 고정 하단 조작부의 공간을 침범해서도 안 됩니다.

## 8. 필수 화면 크기

다음 환경에서 검증해 주세요.

- 320×844
- 360×667
- 390×844
- 1080×1920
- 실제 Replit Preview 새 창으로 열기

특히 **1080px 이상의 넓은 브라우저 창에서 첫 화면 상단이 잘리는 현상**을 반드시 재현·수정해 주세요.

브라우저가 넓어졌을 때 중앙 키오스크 영역의 상단만 잘리는 레이아웃 문제가 있는지도 별도로 확인합니다.

기존 QR 미적용 상태와 v3 QR 모의 프로필 적용 상태 모두 검사해 주세요.

## 9. 실제 사용자 스크롤 시나리오 테스트

각 화면 크기에서 다음 순서로 검사합니다.

1. 새로운 브라우저 창에서 첫 화면 열기
2. 첫 제목이 보이는지 확인
3. 목록을 중간까지 스크롤
4. 증명서 버튼 선택
5. 새로운 발급 화면의 제목이 맨 위부터 보이는지 확인
6. 해당 화면을 다시 아래로 스크롤
7. 다음 버튼 클릭
8. 다음 화면의 상단 표시 확인
9. 전화면으로 돌아가기
10. 돌아온 화면의 시작 위치 확인
11. QR 모달을 열었다 닫기
12. 모달 전후 기존 스크롤 위치 유지 확인
13. 처음화면 복귀
14. 증명서 목록 맨 위 표시 확인
15. 새로운 발급 세션 반복

각 전환의 전후 scrollTop과 첫 번째 제목의 화면 좌표를 기록해 주세요.

**특히 scrollTop=0이라는 값만 확인하지 말고, 실제 첫 번째 제목이 가시 영역 안에 있는지까지 확인해야 합니다.**

## 10. 기존 기능 회귀

다음 기능도 확인합니다.

- QR 도크 첫 화면 전용 표시
- QR 적용 후 하단 모드 자동 실행
- 발급 단계에서도 설정 유지
- 발급 중 QR 도크 제거
- 처음화면 복귀 시 QR 도크 재표시
- 이전 사용자 접근성 프로필 초기화
- 스크롤 안내 정상 표시·숨김
- 스마트 길잡이 타이머 정상 종료
- 주민등록등본 발급 시뮬레이션 완료
- 이중 스크롤 재발 없음
- 가로 넘침 없음
- 키패드 입력 정상

## 11. 수정 범위

우선 무인민원발급기 호스트의 화면 전환 수명주기와 스크롤 관리 로직에서 원인을 확인해 수정해 주세요.

가능하면 화면별 임시 CSS를 추가하는 대신, 공통된 화면 전환 처리에서 해결합니다.

단, 실제 상단 잘림의 원인이 SDK의 viewport·스크롤 계산에 있다면 호스트에서 무리하게 우회하지 마세요.

그 경우 재현 조건과 좌표를 정리하고 공통 SDK에서 수정해야 할 내용을 별도로 보고해 주세요.

이번 작업에서는 SDK v0.5.3 내부 코드와 중앙 서버를 변경하지 않습니다.
