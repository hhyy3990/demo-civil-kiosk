# 무인민원발급기 — SDK v0.3.0 적용 및 범용 자동 보정 검증

현재 무인민원발급기에 `@naebangsik/kiosk-accessibility-sdk@0.2.1`이 설치되어 있습니다.

첨부한 파일은 새로운 공통 SDK v0.3.0입니다.

이번 작업은 SDK를 업데이트하고, 기존 무인민원발급기의 고정 픽셀 글씨와 버튼이 공통 SDK만으로 확대되는지, 확대 과정에서 발생하는 레이아웃 오류가 안전하게 자동 보정되는지 검증하는 것입니다.

## 1. SDK 업데이트

- 첨부된 .tgz 파일을 프로젝트 루트에 저장
- 패키지명과 버전이 `@naebangsik/kiosk-accessibility-sdk@0.3.0`인지 확인
- 기존 v0.2.1을 v0.3.0으로 업데이트
- SDK 내부 코드 수정 금지
- 기존 v0.2.1 아카이브 보존

## 2. 접근성 기능 적용

기존 getActions(), getTextTargets()에 등록된 요소를 대상으로 공통 SDK의 글씨·버튼 확대 기능을 적용해 주세요.

현재 무인민원발급기에서 확인된 기존 수치는 다음과 같습니다.

- 메뉴 글씨: 10px
- 메뉴 버튼 높이: 51px
- 모바일 하단 조작 버튼 높이: 43px

큰 글씨와 큰 버튼 설정 적용 전후에 실제 브라우저의 계산된 크기를 측정해 주세요.

CSS 클래스가 붙었는지만 확인하지 말고, 실제 font-size와 버튼 크기의 변화를 보고해 주세요.

기존 디자인을 직접 수정해 결과를 맞추지 마세요.

## 3. 공통 자동 보정 기능 연결

SDK v0.3.0의 getLayoutRegions() 확장 기능을 활용해 주세요.

무인민원발급기의 다음 영역 중 안전하게 자동 보정 가능한 요소만 등록합니다.

- 증명서 메뉴 그리드
- 주요 조작 버튼 그룹
- 스크롤 영역
- 하단 고정 조작부 및 보호 영역

SDK의 correctLayout()과 getLastLayoutCorrections()를 이용해 프로필 적용 후 레이아웃 오류를 진단하고, 필요한 경우 제한적인 자동 보정을 시도해 주세요.

화면 전환, 동적 요소 변경, 화면 크기 변경 후에도 SDK가 실제 DOM을 기준으로 확대 및 진단을 수행하도록 하되, 불필요한 반복 보정이나 무한 루프가 발생하지 않도록 해 주세요.

무인민원발급기 전용 확대·재배치 CSS를 새로 추가하지 마세요.

## 4. 핵심 검증

다음 설정을 비교해 주세요.

A. QR 적용 전 기본 화면

B. 큰 글씨만 적용

C. 큰 버튼만 적용

D. 큰 글씨 + 큰 버튼

E. 큰 글씨 + 큰 버튼 + 고대비 + 화면 단순화 + 하단 조작

각 설정에서 다음 항목을 확인합니다.

- 메뉴 18개 유지
- 메뉴 글씨 실제 크기
- 메뉴 버튼 실제 높이와 너비
- 주요 확인·이전·처음화면 버튼 크기
- 글씨 잘림 여부
- 버튼 겹침 여부
- 가로 넘침 여부
- 화면 밖으로 밀린 요소 여부
- 하단 조작부에 가려진 콘텐츠 여부
- SDK 자동 보정 시도 횟수 및 성공·롤백 결과

390×844 모바일과 1080×1920 세로 화면에서 검증해 주세요.

자동 진단 결과와 실제 브라우저 화면 확인 결과를 구분해 주세요.

## 5. 세션 초기화 유지

다음 기능이 계속 정상 동작해야 합니다.

- 발급 도중 처음화면 → QR 설정 해제
- 발급 완료 후 처음화면 → QR 설정 해제
- 전화면 → QR 설정 유지
- 세션 종료 후 스마트 길잡이와 음성 안내 중단
- 초기화 후 QR 재스캔 가능

## 6. 기존 발급 흐름 유지

- 주민등록등본 발급 시나리오 유지
- 증명서 메뉴 18개 유지
- 기존 공공기관풍 디자인 유지
- 임의 숫자 입력·지문 확인 시뮬레이션·옵션·가상 결제·완료 유지
- 실제 개인정보 수집·서버 전송 금지

## 7. 범용성 실험 원칙

이번 검증에서는 **SDK 자체를 수정하거나 무인민원발급기 CSS를 수작업으로 최적화하지 마세요.**

화면 오류가 발생하면 먼저 다음 내용을 기록합니다.

1. 어떤 화면과 설정에서 발생했는지
2. 적용 전후 실제 크기
3. SDK 진단 결과
4. 자동 보정이 적용됐는지, 롤백됐는지
5. 해결되지 않은 문제
6. 공통 SDK의 한계인지, 호스트 어댑터의 문제인지

발급 버튼이나 메뉴를 숨겨서 오류를 해결하지 마세요.
