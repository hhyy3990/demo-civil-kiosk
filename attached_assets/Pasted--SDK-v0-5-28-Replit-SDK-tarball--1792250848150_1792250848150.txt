# 무인민원발급기 — 최신 SDK v0.5.28 설치 및 최종 회귀 검증

현재 프로젝트는 **무인민원발급기 Replit**입니다.

첨부한 SDK tarball은 데모커피 공통 SDK에서 360×667 화면의 스마트 길잡이 공간 부족 문제를 수정한 최신 후보입니다.

이번 작업의 목표는 다음과 같습니다.

1. 최신 SDK 설치
2. 실제 결제 화면의 스마트 길잡이 2페이지 표시 확인
3. 기존 접근성 기능 회귀 검증
4. QR와 주민등록등본 발급 전체 흐름 검증

**새 기능·디자인·문구·업무 로직은 변경하지 마세요.**

## 1. 최신 SDK 설치

첨부 파일을 설치하기 전에 다음 정보를 검증하세요.

- 패키지: `@naebangsik/kiosk-accessibility-sdk`
- 버전: `0.5.28`
- 크기: `89,225 bytes`
- SHA-256: `ecbc30f227e162170874064574af4b2899b1a96dd5e12e0486952c9baf55a879`

정보가 일치하지 않으면 설치하지 말고 보고하세요.

일치하면 기존 패키지를 보존한 뒤 최신 tarball을 설치하세요.

같은 v0.5.28이더라도 이전 패키지와 내용이 다릅니다. 의존성 캐시와 Preview를 갱신하고, 실제 브라우저에서 최신 SDK JS와 CSS가 적용되는지 확인하세요.

타입 검사와 빌드도 수행하세요.

## 2. 최우선 — 실제 360×667 스마트 길잡이

이전에 스마트 길잡이가 아예 표시되지 않았던 실제 결제 화면을 우선 검증하세요.

- stepId: `certificate.payment-method`
- 화면 크기: 360×667
- 글씨 매우 크게
- 버튼 크게
- 고대비
- 쉬운 말 켜기
- 스마트 길잡이 켜기
- 하단 조작 80%
- 느린 안내 끄기

기존 스마트 길잡이 원문:

증명서 종류, 발급 부수, 표시 항목과 수수료를 확인해 주세요. 내용이 맞으면 결제 방법을 눌러 가상 결제를 진행하세요.

이전 SDK에서는 본문 공간이 부족하여 4페이지가 필요하다고 판단했고, 최대 2페이지 제한 때문에 안내가 아예 표시되지 않았습니다.

최신 SDK의 독립 테스트에서는 헤더를 44px로 조정하고 본문 공간 52px을 확보하여 2페이지 표시가 가능했습니다.

**이 결과가 실제 무인민원발급기에서도 재현되는지 확인하세요.**

필수 확인:

1. 스마트 길잡이가 실제로 표시되는가?
2. 정확히 2페이지 이내인가?
3. 두 페이지를 합치면 실제 원문 67자와 일치하는가?
4. 본문과 제목이 잘리지 않는가?
5. 페이지 전환 때 안내창이 움직이지 않는가?
6. 상단 위치가 약 8px로 유지되는가?
7. 닫기·접기 버튼의 44×44px 크기가 유지되는가?
8. 하단 업무 영역 80%가 유지되는가?
9. 브라우저 오류와 무한 재귀가 없는가?

실제 DOM의 패널 높이, 헤더 높이, 본문 가용 높이, scrollHeight/clientHeight를 측정해 보고하세요.

본문이 1~2px 넘치는 것으로 측정되면 실제 클리핑 컨테이너와 텍스트 요소를 구분해 확인하세요. 눈으로만 판단하지 말고 잘림 여부를 정확히 보고하세요.

## 3. 표시 시간과 상태 복원

실제 결제 화면에서 다음을 확인하세요.

- 스마트 길잡이 등장 전 `guideDelaySeconds` 대기 유지
- 일반 1페이지: 총 10초
- 일반 2페이지: 총 15초, 약 7.5초 후 전환
- 느린 안내: 총 20초
- 느린 안내 2페이지: 약 10초 후 전환
- 스마트 길잡이 종료 후 기존 쉬운 말 상태 복원
- 기존 쉬운 말 페이지 번호 복원
- 입력·스크롤 중 타이머 불필요한 재시작 없음

실제 결제 안내가 2페이지라면 해당 원문으로 일반 15초와 느린 안내 20초를 확인하세요.

테스트를 위해 업무 안내 문구를 변경하지 마세요.

## 4. 다른 화면 크기 확인

동일한 실제 결제 안내를 다음 환경에서도 확인하세요.

- 320×844
- 390×844
- 1080×1920

각 화면에서 다음을 기록하세요.

- 1페이지 또는 2페이지 표시 여부
- 스마트 길잡이 미표시 여부
- 원문 누락·중복
- 본문 잘림
- 상단 패널 위치
- 조작부 겹침 여부

3페이지 이상 필요해 스마트 길잡이가 억제된다면 해결된 것으로 보고하지 말고 해당 화면 크기와 측정값을 남기세요.

## 5. 쉬운 말 안내 회귀

다음 기존 화면도 확인하세요.

- `civil.main-menu`
- `certificate.type-selection`
- `certificate.id-input`

첫 메뉴에서 기존 문구가 유지되는지 확인하세요.

제목: 쉬운 말 안내가 켜져 있어요.

본문: 업무를 선택하면 어려운 말을 쉽게 설명해 드려요.

주민등록표 종류 안내와 주민등록번호 안내에서는 다음 사항을 확인하세요.

- 원문 보존
- 잘림 없음
- 한 글자씩 비정상적 분할 없음
- 66·137페이지 오류 재발 없음
- 이전·다음 정상
- 상단 Y=8px 유지
- 무한 재귀 없음

이전에 발견된 페이지 번호의 비연속적 변화도 확인하고, 발생하면 실제 표시 순서와 함께 기록하세요.

단, 이번 작업에서 임의로 페이지 분할 방식을 다시 변경하지 마세요.

## 6. 자동 하단 80% 및 스크롤 안내

기존 규칙을 그대로 유지하세요.

- 쉬운 말 켜기 + viewportMode null → 첫 메뉴 포함 자동 하단 80%
- 명시적 60·70·80% → 선택값 유지
- 쉬운 말 끄기 + viewportMode null → 일반 화면

추가로 다음을 확인하세요.

- 하단 QR 도크 위치
- 스크롤 안내가 실제 스크롤 영역 아래쪽에 안정적으로 표시되는지
- 스크롤 중 위치 점프가 없는지
- 끝까지 내리면 스크롤 안내가 사라지는지
- 업무 버튼 클릭을 방해하지 않는지

## 7. 실제 QR와 전체 발급 검증

스마트 길잡이의 핵심 오류가 해결되었다면 중단됐던 검증을 이어서 수행하세요.

### QR 검증

- QR v1~v4 파싱 호환성
- 실제 중앙 Production QR 조회 경로
- 유효한 QR 적용
- 이미 폐기된 QR의 거부 동작
- QR 재스캔 동작
- 접근성 설정 적용 및 초기화
- 카메라 QR 인식(테스트 환경에서 가능할 때만)

합성 QR 응답 테스트와 실제 Production 서버 조회를 명확히 구분해 보고하세요.

실제 Production DB에 새로운 프로필을 만들거나 데이터를 수정하지 마세요. 기존에 사용할 수 있는 안전한 테스트 QR이 없다면 무리해서 생성하지 말고 해당 검증은 미실행으로 기록하세요.

### 전체 발급 흐름

기존 주민등록등본 발급 흐름을 그대로 검증하세요.

- 첫 메뉴
- 증명서 종류 선택
- 주민등록번호 키패드
- 지문 확인 시뮬레이션
- 표시 항목 선택
- 발급 부수 선택
- 신청 내용 확인
- 가상 결제
- 인쇄 시뮬레이션
- 발급 완료
- 15초 후 첫 메뉴 복귀
- 접근성 설정 및 입력값 초기화

실제 주민등록번호 등 개인정보는 입력하지 마세요. 임의 테스트 숫자만 사용하세요.

기존에 정상 확인했던 320×844 발급 흐름이 유지되는지 확인하고, 360×667에서도 핵심 흐름을 완료하세요.

## 8. 오류 발생 시

공통 SDK 결함이 발견되면 무인민원발급기 호스트에서 우회 수정하지 마세요.

다음을 기록하세요.

- 화면 크기와 설정
- stepId
- 실제 표시 문구
- DOM 높이 측정값
- 필요한 페이지 수
- 잘림 또는 미표시 상태
- 브라우저 오류 및 관련 로그

핵심 오류라면 해당 검증을 중단하고 보고하세요.

문구 축약, CSS 덮어쓰기, SDK 내부 직접 수정, 새로운 표시 방식 도입은 사용자 승인 없이 하지 마세요.
