# 내 방식 QR — 무인민원발급기 SDK v0.5.4 설치 및 범용 화면 전환 스크롤 초기화 적용

현재 무인민원발급기 프로젝트에는 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.3`이 설치되어 있습니다.

첨부한 파일은 SDK v0.5.4 tarball입니다.

이번 v0.5.4에는 다음 공개 API가 추가됐습니다.

`notifyScreenChange(screenId: string): boolean`

이 API는 호스트가 실제 업무 화면 변경을 알리면, SDK가 문서 및 등록된 스크롤 영역을 확인하고 새 화면을 맨 위부터 표시하도록 처리합니다.

이번 작업은 기존 무인민원발급기에서 확인됐던 스크롤 위치 잔류 문제를 이 공개 API로 해결하는 것입니다.

**SDK 내부를 수정하거나 무인민원발급기 전용 스크롤 우회 코드를 작성하지 마세요. 공통 SDK 공개 API를 연결하는 방식으로 해결해야 합니다.**

중앙 QR 서버·DB, 데모커피 프로젝트는 수정하지 않습니다.

## 1. SDK v0.5.4 설치

첨부 tarball을 확인하고 기존 v0.5.3에서 업데이트해 주세요.

확인 사항:

- 패키지명 `@naebangsik/kiosk-accessibility-sdk`
- 설치 버전 `0.5.4`
- tarball 내부 버전과 설치된 패키지 버전 일치
- SDK JavaScript·CSS 정상 로드
- 새 `notifyScreenChange()` 공개 API 존재
- 기존 `applyProfile()`, `setViewportMode()`, `createQrEntryDock()`, `endSession()` 유지
- 기존 v0.5.3 아카이브 보존

SDK의 내부 소스나 설치된 node_modules 코드는 수정하지 마세요.

## 2. 기존 오류 재현 조건

v0.5.3에서 확인된 문제는 다음과 같습니다.

### 사례 A — QR 적용 후 다음 화면 전환

390×844에서 큰 글씨·큰 버튼·고대비·하단 80% v3 프로필을 모의 QR 응답으로 적용했습니다.

- 기존 `.stage` 높이 541px
- 스크롤 범위 658px
- 실제 휠로 80px 이동
- 증명서 메뉴 선택
- 업무 화면 ID는 바뀌었지만 다음 화면에서도 `.stage.scrollTop=80px` 유지

### 사례 B — 처음화면 복귀

390×844에서 발급 화면 중 처음화면으로 이동했습니다.

- 이전 화면에서 document가 스크롤 가능
- 처음화면 복귀 시 QR 도크 재활성화
- `.stage.scrollTop=108px`
- 첫 화면 제목이 y=116에서 y=8로 밀림
- 상단 헤더가 잘린 것처럼 표시됨

이번 작업에서 두 사례를 동일한 조건으로 검증해 주세요.

새 탭 최초 진입에서는 상단 잘림이 재현되지 않았다는 기존 진단도 참고합니다.

## 3. 화면 ID와 실제 업무 단계 분석

수정 전에 현재 무인민원발급기의 화면 전환 상태를 확인해 주세요.

- 첫 화면
- 증명서 선택 후 발급 단계
- 주민등록번호 입력
- 지문 확인
- 발급 옵션
- 수수료·부수 선택
- 신청 내용 확인
- 가상 결제
- 인쇄 중
- 발급 완료
- 전화면 및 처음화면 복귀

각 단계가 어떤 state 또는 화면 식별자로 구분되는지 분석합니다.

**SDK에는 업무 화면의 이름을 하드코딩하지 않고, 호스트가 안정적인 screenId만 전달합니다.**

같은 업무 화면에서 단순히 숫자를 입력하거나 선택값을 변경했다고 별도의 screenId로 처리하면 안 됩니다.

모달 표시 여부나 스마트 길잡이 상태도 screenId에 포함하지 마세요.

## 4. 공통 화면 전환 API 연결

SDK 공개 API `notifyScreenChange(screenId)`를 사용합니다.

연결 원칙:

1. 호스트의 실제 업무 화면 식별자를 확인
2. 화면이 렌더링된 뒤 해당 screenId를 SDK에 전달
3. SDK가 이전 식별자와 비교
4. 새 화면이면 SDK에서 스크롤 소유자 및 레이아웃 처리
5. 같은 화면의 재렌더링은 초기화하지 않음

React를 사용한다면 SDK 인스턴스의 생명주기와 화면 상태 변경 시점을 확인한 뒤 적절한 effect에서 호출해 주세요.

예시 형태:

```tsx
useLayoutEffect(() => {
  sdk.notifyScreenChange(screenId);
}, [sdk, screenId]);
```

이 코드는 개념적인 예시입니다. 실제 SDK 인스턴스가 안정적으로 유지되는지, 화면이 DOM에 반영되는 시점이 올바른지 확인해 프로젝트 구조에 맞게 적용해 주세요.

특히 화면 상태가 바뀌는 도중 오래된 SDK 인스턴스를 호출하거나, SDK 인스턴스를 매 렌더링마다 새로 생성하지 않도록 주의합니다.

**호스트에서 별도로 `window.scrollTo(0,0)`, `.stage.scrollTop=0`, 반복 setTimeout 등을 추가하지 마세요.**

스크롤 초기화는 SDK 공개 API가 담당해야 합니다.

## 5. 기존 scrollArea 어댑터 등록 검토

이전 진단에서 호스트 어댑터는 모든 화면에 `.stage`를 scrollArea로 등록하고 있었습니다.

그러나 일부 긴 입력 화면에서는 document가 실제 스크롤 소유자였습니다.

다음 사항을 확인해 주세요.

- 화면별 실제 스크롤 소유자
- 현재 어댑터가 반환하는 scrollArea
- SDK가 document.scrollingElement를 함께 처리하는지
- 스크롤 소유자가 변경되는 화면
- 하단 viewport 활성화 시 SDK가 지정한 스크롤 영역
- QR 도크 생성·제거 시 스크롤 소유자 변화

기존 어댑터가 공개 SDK 계약에 맞지 않는다면 최소한으로 수정할 수 있습니다.

단, **어댑터에서 화면마다 강제로 스크롤을 초기화하는 우회 로직은 작성하지 마세요.**

기존 `.stage` 등록이 SDK 계약상 적절하고 document 처리만으로 해결된다면 불필요하게 변경하지 않아도 됩니다.

## 6. 실제 화면 전환 정책

다음 경우에는 새 화면의 상단부터 보여야 합니다.

- 첫 화면 → 발급 화면
- 발급 화면 → 다음 입력 단계
- 입력 단계 → 지문 확인
- 지문 확인 → 발급 옵션
- 발급 옵션 → 수수료·부수 선택
- 신청 내용 확인 → 결제
- 결제 → 완료
- 전화면으로 이전 업무 단계 복귀
- 업무 중 처음화면 복귀
- 발급 완료 후 처음화면 복귀

반면 다음 경우에는 사용자의 스크롤 위치를 유지합니다.

- 같은 화면에서 입력값 변경
- 발급 부수 변경
- 선택 항목 변경
- QR 모달 열기·닫기
- 발급 불가 안내 모달 열기·닫기
- 스마트 길잡이 표시·닫기
- 스크롤 안내 표시·숨김
- 브라우저 화면 크기 변경
- 같은 screenId의 React 재렌더링

새 화면 진입 시 초기화하고, 같은 화면의 사용자 조작은 보존하는 것이 핵심입니다.

## 7. 화면 상단 가시성 검증

`scrollTop=0`만 확인하지 말고 실제 첫 번째 콘텐츠가 보이는지도 검증합니다.

각 화면에서 다음을 측정해 주세요.

- document.scrollTop
- `.stage.scrollTop`
- SDK 등록 scrollArea.scrollTop
- 실제 스크롤 소유자
- 새 화면 첫 제목의 boundingClientRect
- 현재 콘텐츠 표시 영역의 boundingClientRect
- 첫 제목이 표시 영역 안에 있는지
- 상단 헤더가 잘리지 않는지

방법 B에서는 콘텐츠 영역이 화면 하단 60·70·80%에 배치되므로, 화면의 절대 y좌표가 0이 아닌 것은 정상입니다.

**중요한 것은 새 업무 화면의 첫 콘텐츠가 해당 표시 영역의 맨 위부터 보이는지입니다.**

## 8. QR 도크와 하단 viewport 결합

다음 상태에서 모두 확인해 주세요.

- QR 미적용 일반 모드
- v3 viewportMode null
- 하단 60%
- 하단 70%
- 하단 80%
- 아주 큰 글씨·큰 버튼·고대비 + 하단 60%
- 아주 큰 글씨·큰 버튼·고대비 + 하단 70%
- 아주 큰 글씨·큰 버튼·고대비 + 하단 80%

화면 전환 시:

- QR 도크 활성화·비활성화 정상
- 기존 하단 고정 버튼 유지
- 하단 표시 영역 자동 재계산
- 글씨·버튼 크기 유지
- 화면 전환 후 첫 콘텐츠 표시
- 이중 스크롤 없음
- 가로 넘침 없음
- 스크롤 안내 정상 동작

QR 프로필을 적용한 뒤에는 개발용 viewport 테스트 컨트롤이 프로필 설정을 덮어쓰지 않는 기존 정책을 유지합니다.

## 9. 스크롤 초기화의 안정성

v0.5.4 SDK는 화면 전환 뒤 animation frame을 사용해 레이아웃 안정화를 확인합니다.

다음 상황을 시험해 주세요.

- 화면 변경 직후
- 다음 프레임
- 0.1초 후
- 0.5초 후
- 1초 후
- 3초 후

새 화면의 첫 콘텐츠가 계속 보여야 합니다.

또한 화면 전환 후 사용자가 직접 스크롤을 시작했다면 SDK의 늦은 초기화가 사용자를 다시 맨 위로 강제로 돌려서는 안 됩니다.

SDK의 내부 동작이 실제 호스트에서 이 조건을 만족하지 못한다면, 호스트 전용 타이머를 추가하지 말고 **SDK 공통 문제로 재현 조건을 보고해 주세요.**
