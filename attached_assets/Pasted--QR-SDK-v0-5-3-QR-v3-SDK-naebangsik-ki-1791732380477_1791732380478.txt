# 내 방식 QR — 무인민원발급기 SDK v0.5.3 설치 및 QR 프로필 v3 자동 적용 검증

현재 무인민원발급기 프로젝트에는 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.2`가 설치되어 있습니다.

첨부한 파일은 새로운 SDK v0.5.3 tarball입니다.

중앙 '내 방식 QR' 서비스의 Development 환경에서는 프로필 스키마 v3가 구현됐으며, 사용자가 다음 하단 조작 설정을 선택할 수 있습니다.

- 사용하지 않음: `viewportMode: null`
- 아래쪽 60%: `{ "mode": "bottom", "heightPercent": 60 }`
- 아래쪽 70%: `{ "mode": "bottom", "heightPercent": 70 }`
- 아래쪽 80%: `{ "mode": "bottom", "heightPercent": 80 }`

SDK v0.5.3에서는 `applyProfile()`이 v3 프로필의 `preferences.viewportMode`를 읽어 기존 방법 B 하단 조작 모드를 자동 적용하도록 구현됐습니다.

이번 작업에서는 무인민원발급기의 SDK를 v0.5.3으로 업데이트하고, 기존 QR 조회·적용 경로에서 하단 비율이 실제로 자동 적용되는지 검증해 주세요.

**중앙 Production 서비스는 아직 v3로 배포되지 않았으므로, 이번 검증은 v3 모의 API 응답을 사용합니다. 실제 중앙 서비스 연동 성공으로 보고하면 안 됩니다.**

## 2. QR v3 자동 적용 연결 확인

기존 무인민원발급기에는 다음 흐름이 있습니다.

1. 첫 화면의 '내 QR로 화면 설정' 버튼 클릭
2. QR 카메라 또는 주소·토큰 직접 입력
3. 중앙 QR 프로필 조회 API 호출
4. SDK 프로필 검증
5. SDK 접근성 설정 적용
6. 발급 업무 진행

이 흐름을 유지하면서 v3 프로필이 정상 전달되는지 확인해 주세요.

v3 프로필 예시:

```json
{
  "schemaVersion": 3,
  "preferences": {
    "textSize": "extraLarge",
    "buttonSize": "large",
    "contrast": "high",
    "easyLanguage": false,
    "viewportMode": {
      "mode": "bottom",
      "heightPercent": 70
    },
    "smartGuide": true,
    "guideDelaySeconds": 10,
    "voiceGuidance": false
  }
}
```

이 JSON은 핵심 설정을 보여주는 예시입니다. 실제 SDK의 필수 메타데이터와 응답 검증 계약을 확인한 뒤 그 형식에 맞는 모의 응답을 사용해 주세요.

**개발용 `setViewportMode()`를 직접 호출하는 것이 아니라, QR 조회 응답을 기존 `applyProfile()` 흐름에 전달하여 자동 적용되는지 검증해야 합니다.**

검증할 값:

- `viewportMode: null`
- 하단 60%
- 하단 70%
- 하단 80%
- 잘못된 비율 65%
- 잘못된 문자열 `"70"`
- 잘못된 mode 값

잘못된 프로필은 적용을 거부하고 기존 성공적으로 적용된 설정을 의도치 않게 변경하지 않아야 합니다.

## 3. 첫 화면 QR 도크와 하단 모드 결합

기존 무인민원발급기의 QR 도크와 고정 하단 조작부를 유지합니다.

이전 v0.5.2에서 확인된 구조:

- 첫 화면 전용 QR 도크
- 기존 처음화면·전화면 등 고정 하단 조작부
- 증명서 메뉴 18개
- `.stage` 내부 스크롤
- 스크롤 안내 및 스마트 길잡이

v3 QR 적용 시 다음을 확인합니다.

- QR 도크는 첫 화면에 계속 표시
- QR 적용 즉시 선택 비율 활성화
- 글씨와 버튼 크기를 축소하지 않음
- QR 도크의 실제 높이를 측정
- 고정 조작부의 실제 높이를 측정
- 두 영역을 제외한 공간을 기준으로 60·70·80% 적용
- 메뉴 영역의 내부 스크롤 유지
- QR 도크·고정 버튼·스크롤 안내가 겹치지 않음
- 모든 증명서 메뉴 접근 가능

특히 v0.5.3에서는 큰 글씨로 QR 도크 높이가 늘어날 수 있습니다.

고정 72px을 가정하지 말고 **실제 DOM 측정 높이**를 기준으로 검사해 주세요.

## 4. 발급 업무 중 설정 유지

첫 화면에서 v3 QR을 적용한 뒤 주민등록등본 발급 시뮬레이션을 진행합니다.

확인 사항:

- 발급 단계에 들어가면 QR 도크가 사라짐
- 하단 조작 60·70·80% 설정은 유지
- QR 도크가 제거된 만큼 가용 높이를 다시 계산
- 기존 하단 고정 업무 버튼 유지
- 글씨·버튼 크기·고대비 설정 유지
- 스마트 길잡이·스크롤 안내 유지
- 전화면 이동 시 접근성 설정 유지
- 주문 또는 발급 중 QR 재설정 버튼 없음

**발급 화면으로 이동했다고 viewportMode가 null로 초기화되면 안 됩니다.**

QR 도크의 표시 수명주기와 QR 프로필의 접근성 세션은 서로 독립적으로 관리합니다.

## 5. 처음화면 복귀 및 세션 초기화

기존 `sdk.endSession()` 호출 정책을 유지합니다.

- 발급 완료 후 처음화면 복귀
- 발급 진행 중 처음화면 버튼으로 복귀
- QR 프로필의 viewportMode 해제
- 큰 글씨·큰 버튼·고대비 등 이전 설정 제거
- 스마트 길잡이 타이머 및 음성 안내 취소
- 기존 메뉴 18개 복원
- QR 도크 재표시
- 다음 이용자의 새로운 QR 적용 가능

특히 `60% → 세션 종료 → 80%`처럼 다음 이용자 프로필을 적용했을 때 이전 비율이 남지 않아야 합니다.

## 6. QR 프로필 교체 검증

첫 화면에서 다음 전환을 시험합니다.

- null → 60%
- 60% → 70%
- 70% → 80%
- 80% → null
- 60% → 80%
- 동일한 70% 두 번 적용
- v3 → v2
- v2 → v3
- 정상 프로필 적용 후 잘못된 QR 입력
- 정상 프로필 적용 후 QR 모달 취소

다음 문제는 없어야 합니다.

- 높이가 반복 적용할 때마다 누적해서 줄어듦
- QR 도크 중복 생성
- 문서와 내부 콘텐츠 이중 스크롤
- 이전 프로필 스타일 잔류
- 실패하거나 취소한 QR 때문에 기존 설정 소실
- 모달 열기·닫기 후 스크롤 위치 변경

기존 v1/v2 프로필은 `viewportMode: null`로 정규화하고 이전 `bottomControls`만으로 방법 B를 실행하지 않습니다.

## 7. 스크롤 안내 회귀

v0.5.2에서 해결한 `no-safe-space` 문제를 유지해야 합니다.

기본·60·70·80%에서 다음 동작을 확인해 주세요.

- 스크롤 가능한 콘텐츠가 있으면 안내 표시
- 안내가 QR 도크 및 고정 버튼 위쪽에 배치
- 일반 메뉴와 일부 겹침은 허용
- 안내는 메뉴 터치를 방해하지 않음
- 최하단 도달 시 안내 숨김
- 위로 복귀하면 안내 재표시
- 스마트 길잡이 및 모달 표시 시 안내 숨김
- 스마트 길잡이·모달 종료 후 필요한 경우 안내 복귀

기존 안내 문구를 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

스크롤할 콘텐츠가 없다면 안내가 표시되지 않는 것이 정상입니다.

## 8. 작은 화면 및 키패드 검증

다음 화면 크기에서 검사합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920

각각 다음 설정을 검증합니다.

A. QR 미적용

B. v3 viewportMode null

C. v3 하단 60%

D. v3 하단 70%

E. v3 하단 80%

F. 아주 큰 글씨 + 큰 버튼 + 고대비 + 하단 60%

G. 아주 큰 글씨 + 큰 버튼 + 고대비 + 하단 70%

H. 아주 큰 글씨 + 큰 버튼 + 고대비 + 하단 80%

측정 항목:

- QR 도크 top / bottom / height
- 기존 고정 조작부 top / bottom / height
- 실제 하단 표시 영역 높이
- `.stage`의 scrollHeight / clientHeight
- 문서 scrollHeight / clientHeight
- 실제 스크롤 소유자
- 스크롤 안내 좌표 및 충돌 여부
- 가로 넘침
- 마지막 증명서 메뉴 표시·클릭
- 숫자 키패드 0~9 입력
- 터치 영역 크기
- 스크롤 후 3초간 위치 안정성

360×667의 좁은 화면에서는 고정 UI가 콘텐츠를 지나치게 압박하지 않는지 특히 확인해 주세요.

화면 높이가 부족한 경우 필수 버튼이나 메뉴를 가려서 성공 처리하면 안 됩니다.

## 10. 개발용 하단 모드 테스트 기능

기존 `?viewport-test=1` 테스트 화면은 유지해 주세요.

단, 다음 원칙을 적용합니다.

- 일반 사용자 화면에서 보이지 않음

- 개발용 비율이 QR 설정을 덮어쓰지 않음
- QR 프로필 적용 실패 시 개발용 상태로 잘못 전환되지 않음

기존 개발용 컨트롤을 삭제하거나 새 기능으로 재구현할 필요는 없습니다.

### 최종 성공 기준

**1. v3 QR 프로필의 `viewportMode`가 개발용 버튼 없이 자동 적용됩니다.**

**2. 첫 화면에서 QR 도크와 기존 하단 조작부를 유지한 채 60·70·80% 모드가 작동합니다.**

**3. 발급 화면에서도 선택한 비율이 유지되며, QR 도크 제거에 맞춰 영역이 재계산됩니다.**

**4. 발급 완료 또는 처음화면 복귀 시 이전 설정이 완전히 초기화됩니다.**

**5. 스크롤 안내·증명서 메뉴·키패드·발급 흐름이 정상 작동합니다.**

**6. 기존 v0.5.2에서 해결한 이중 스크롤과 no-safe-space 문제가 재발하지 않습니다.**

모든 결과는 실제 측정값으로 확인하고, 모의 응답·브라우저 시뮬레이션과 실제 중앙 서버·기기 검증을 구분해 보고해 주세요.
