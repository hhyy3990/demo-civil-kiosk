# 내 방식 QR — 무인민원발급기 SDK v0.5.2 업데이트 및 스크롤 안내 최종 검증

첨부한 파일은 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.2` tarball입니다.

현재 무인민원발급기에는 SDK v0.5.1이 적용되어 있으며, 다음 기능은 이미 브라우저에서 검증했습니다.

- 첫 화면 QR 하단 도크
- 기존 하단 고정 조작부와 QR 도크의 공존
- 18개 증명서 메뉴 접근
- 하단 조작 60%·70%·80%
- QR v1/v2 프로필 적용
- 주민등록등본 발급 전체 시뮬레이션
- 발급 중 접근성 설정 유지
- 처음화면 복귀 시 SDK 세션 초기화
- QR·안내 모달의 스크롤 위치 유지

다만 **기본 화면에서 스크롤 가능한 콘텐츠가 있음에도 SDK의 '↓ 아래에도 내용이 있어요' 안내가 표시되지 않는 문제**가 있었습니다.

v0.5.2는 해당 `no-safe-space` 문제를 해결하기 위해 공통 스크롤 안내 배치 로직을 수정한 버전입니다.

이번 작업의 목적은 무인민원발급기에 v0.5.2를 설치하고, 해당 문제가 실제 호스트에서도 해결되는지 검증하는 것입니다.

## 1. SDK v0.5.2 설치

첨부 tarball을 확인한 후 기존 v0.5.1에서 v0.5.2로 업데이트해 주세요.

필수 확인:

- 패키지명: `@naebangsik/kiosk-accessibility-sdk`
- 버전: `0.5.2`
- 설치된 node_modules의 실제 버전 확인
- 새 SDK JavaScript와 CSS가 모두 로드되는지 확인
- 이전 v0.5.1의 캐시나 빌드 결과를 잘못 사용하는지 확인
- `createQrEntryDock()` 및 `setViewportMode()` 등 기존 공개 API 유지
- QR 프로필 v1/v2 호환성 유지

SDK 내부 소스는 수정하지 마세요.

현재 정상 작동하는 무인민원발급기 호스트 코드를 최대한 유지하고, 필요한 패키지 설치 및 연결 변경만 수행합니다.

## 2. 기존 no-safe-space 현상 재검증

이전 v0.5.1에서 다음 상태가 확인됐습니다.

390×844 화면 기준:

- QR 도크: y=667~739px
- 기존 고정 하단 조작부: y=739.6~844px
- 스크롤 소유자: `.stage`
- 문서 스크롤 범위: 0px
- 첫 화면에 스크롤 가능한 증명서 메뉴 18개
- 기본 화면에서 `no-safe-space`로 안내 미표시
- 하단 60·70·80% 모드에서는 안내 정상 표시

v0.5.2 설치 후 동일한 화면에서 다시 측정해 주세요.

특히 **기본 화면의 스크롤 안내가 정상적으로 나타나는지**가 이번 작업의 최우선 검증 항목입니다.

## 3. 스크롤 안내 동작 확인

기본 화면에서 다음 순서로 검증해 주세요.

1. 첫 화면 상단으로 이동
2. 아래에 추가 메뉴가 있는지 확인
3. `↓ 아래에도 내용이 있어요` 또는 해당 상황에 맞는 SDK 안내 문구 표시 확인
4. 안내의 화면 좌표 측정
5. QR 도크 및 기존 하단 조작부와 겹치지 않는지 확인
6. 콘텐츠를 중간까지 스크롤
7. 안내 표시 상태 확인
8. 마지막 증명서 메뉴까지 스크롤
9. 스크롤 최하단에서 안내가 사라지는지 확인
10. 다시 위로 스크롤하면 안내가 재표시되는지 확인

기존 문구를 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

단순히 DOM에 안내 요소가 있다는 것만으로 성공 처리하지 마세요.

실제 화면에 표시되는지, 가려지지 않는지, 위치가 정확한지 확인해야 합니다.

## 4. QR 도크·고정 조작부와 겹침 검사

v0.5.2에서는 SDK가 QR 도크와 고정 조작부의 실제 위치를 측정해 안내 위치를 결정합니다.

무인민원발급기에서 다음 요소의 실제 bounding rectangle을 확인해 주세요.

- 스크롤 안내
- QR 도크
- QR 버튼
- 고정 하단 조작부
- 처음화면·전화면·확인 버튼
- 현재 콘텐츠 스크롤 영역

반드시 확인할 사항:

- 스크롤 안내와 QR 도크가 겹치지 않음
- 스크롤 안내와 필수 고정 버튼이 겹치지 않음
- QR 도크와 고정 조작부도 서로 겹치지 않음
- 안내 문구가 화면 밖으로 잘리지 않음
- 일반 메뉴와 일부 겹치더라도 클릭을 방해하지 않음
- 안내가 스크롤 제스처를 가로채지 않음

SDK 안내 요소는 일반 콘텐츠의 클릭을 방해하지 않아야 합니다.

기존 메뉴와 버튼의 위치를 임의로 옮겨서 안내 공간을 확보하지 마세요.

## 5. 기본 화면 및 하단 모드 회귀

다음 네 상태를 각각 확인합니다.

A. 기본 화면 + QR 도크 + 고정 조작부

B. 하단 60% + QR 도크 + 고정 조작부

C. 하단 70% + QR 도크 + 고정 조작부

D. 하단 80% + QR 도크 + 고정 조작부

각 상태에서 다음을 검증해 주세요.

- 스크롤 안내 표시
- 최하단에서 안내 숨김
- 위로 복귀 시 안내 재표시
- 실제 스크롤 소유 영역 하나
- 이중 스크롤 없음
- 메뉴 18개 모두 접근 가능
- 마지막 메뉴 클릭 가능
- QR 버튼 정상 클릭
- 기존 하단 버튼 정상 클릭
- 가로 넘침 없음
- 글씨·버튼 크기 유지

하단 모드의 계산 원칙은 기존과 동일하게 유지합니다.

**QR 도크 및 등록된 고정 조작부를 제외한 공간에서 60%·70%·80%를 계산합니다.**

개발용 `?viewport-test=1` 기능도 그대로 유지합니다.

중앙 QR 프로필의 기존 `bottomControls` 값만으로 방법 B를 자동 실행하지 마세요.

## 6. 스마트 길잡이·모달 우선순위

스크롤 안내와 다른 안내 요소가 겹치지 않는지 확인합니다.

- 스마트 길잡이가 표시되면 스크롤 안내 숨김
- 스마트 길잡이가 닫히면 스크롤 필요 여부에 따라 안내 재표시
- QR 모달이 열리면 스크롤 안내가 모달 조작을 방해하지 않음
- 발급 불가 안내 모달에서도 동일
- 모달 닫기 전후 `.stage.scrollTop` 유지
- 안내가 나타나거나 사라질 때 스크롤 위치가 튀지 않음
- 세션 종료 후 스마트 길잡이 타이머와 음성 안내가 남지 않음

특히 기존에 수정한 발급 불가 모달의 스크롤 점프 방지 구조는 유지해야 합니다.

## 7. 반응형 화면 검증

다음 화면 크기에서 테스트합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920

각 화면에서 기본·60%·70%·80%를 확인합니다.

측정 항목:

- 스크롤 안내 top / bottom / height
- QR 도크 top / bottom / height
- 기존 고정 조작부 top / bottom / height
- 충돌 여부
- scrollHeight / clientHeight / 최대 스크롤 거리
- 실제 document 스크롤 거리
- 메뉴 18개 접근 가능 여부
- 마지막 메뉴 클릭 결과
- 3초 후 스크롤 위치 안정성
- 화면 너비 초과 여부

특히 360×667 같은 세로 공간이 작은 화면에서 안내가 고정 버튼을 가리지 않는지 확인해 주세요.

보호 영역 때문에 정말 안내를 표시할 공간이 없다면, 실제 측정값과 이유를 보고해 주세요. 고정 버튼을 덮는 방식으로 해결하면 안 됩니다.

## 8. QR 프로필·발급 흐름 회귀

이번 작업은 스크롤 안내 수정이므로 기존 기능을 새로 구현하지 않습니다.

하지만 다음 동작이 유지되는지 확인합니다.

### QR 진입

- 첫 화면에서 QR 도크 표시
- QR 버튼 클릭 시 기존 QR 모달 열림
- 카메라·주소·토큰 직접 입력 UI 유지
- QR 적용 이후 첫 화면에서도 도크 유지
- 발급 단계로 이동하면 QR 도크 제거
- 발급 중 별도 QR 진입 경로 없음

### 발급 흐름

1. 증명서 선택
2. 테스트 번호 입력
3. 가상 지문 확인
4. 발급 옵션 선택
5. 수수료 및 부수 선택
6. 신청 내용 확인
7. 가상 결제
8. 인쇄·발급 완료
9. 처음화면 복귀
10. 접근성 설정 초기화 및 QR 도크 재표시

기존 QR v1·v2 모의 프로필을 이용해 접근성 적용 상태에서도 발급 흐름을 확인해 주세요.

실제 중앙 QR 서버 연결 여부와 모의 응답 검증은 반드시 구분해 주세요.

## 9. 원인별 문제 처리 원칙

업데이트 후에도 안내가 보이지 않는다면 바로 호스트 CSS를 추가하지 마세요.

먼저 다음을 구분합니다.

A. 새 SDK v0.5.2가 실제로 설치·로드되지 않은 문제

B. 스크롤 영역을 어댑터에 잘못 등록한 문제

C. 고정 하단 조작부의 영역을 잘못 등록한 문제

D. QR 도크의 실제 위치를 SDK가 감지하지 못하는 문제

E. SDK의 스크롤 안내 후보 위치 계산 자체의 문제

F. 실제 화면에 안내를 표시할 물리적인 공간이 부족한 문제

호스트의 어댑터 등록 오류라면 기존 계약에 맞춰 최소한으로 수정할 수 있습니다.

그러나 SDK 공통 배치 로직의 결함이라면 무인민원발급기 전용 CSS나 새 안내 컴포넌트로 우회하지 말고, 재현 조건과 측정값을 보고해 주세요.

공통 SDK 수정이 필요하면 데모커피 SDK 개발 프로젝트에서 별도 작업을 진행하겠습니다.
