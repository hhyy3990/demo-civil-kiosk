---
name: Autoscale startup health retries
description: Observed Autoscale startup checks before the Civil process begins serving requests.
---

When investigating a failed deployment, distinguish pre-listener health-check errors from responses generated by the app. In a successful diagnostic deployment, Replit recorded connection refusal and HTTP 500 health-check results before the Node process logged startup; the process then listened and returned HTTP 200.

**Why:** An early failed probe did not by itself prevent the diagnostic deployment from becoming healthy, so treating that first error as the root cause would be misleading.

**How to apply:** Correlate health-check timestamps with revision-scoped runtime startup and listen logs. Do not add an early “healthy” response unless the real app handler is ready.
